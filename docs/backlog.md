# 의존 순서의 작은 백로그

작은 단위의 의존 순서와 구현 상태를 기록한다. 날짜별 항목은 완료된 작업과 후속 계획을 구분하며 미래 구현을 완료로 표시하지 않는다.

## 현재 단계: 기획 검토 우선

현재는 [MES·제품 탄소 데이터 서비스 기획 검토본](planning/README.md)을 검토하는 단계다. 기존 범용 RAG 코드와 아래 구현 후보를 보존하며, 제품 구현·출시·인증 완료를 뜻하지 않는다.

1. 기획 안내의 읽는 순서대로 제품 방향 → MES 업무 → 공통 데이터·보안 → 탄소 방법 → 탄소 업무 → 출시·사업 → AI·의사결정을 검토한다. 빠른 방향 검토는 제품 방향과 AI·의사결정부터 시작한다.
2. [개발 착수 승인 TODO](planning/06-ai-discovery-and-decisions.md#8-개발-착수-승인-todo)를 선행조건으로 삼는다. 첫 산업·공장·제품·공정·사용 목적·산정 경계와 실제 표본, 정상·예외·정정 흐름, 권한·계산 정책을 확인한다.
3. 보안·복구·운영·가격·데이터 및 계수 사용 권리·외부 공유 범위의 미결정을 기록하고 담당자와 확인한다. 제안 수치나 산업 가설을 확정 사실로 바꾸지 않는다.
4. 기획 검토와 개발 범위 승인 후 기존 포트·API·데이터 구조에 매핑하고 구현 일정과 하루 범위를 다시 정한다. 미결정이 남으면 해당 구현은 보류한다.

## 이후 게이트

1. 실제 baseline 실행: corpus/ACL snapshot·버전·비용·접속 환경이 준비된 뒤 한 단계씩 진행한다. mock을 실제 품질 지표로 쓰지 않는다.
2. PageIndex 비교: 공식 구현과 프로토콜을 먼저 고르고 같은 corpus/예산의 계약부터 검증한다. Elasticsearch 작업과 동시에 전체 구현하지 않는다.
3. 접근권한/문서 변경: policy revision·tombstone·멱등성·역순 이벤트를 작은 항목으로 나눈다. 수집·DB·outbox를 하루에 만들지 않는다.
4. 운영 테스트: 실제 인증, timeout/retry, rate limit, 관측성, 부하를 각각 별도 항목으로 계획한다. 운영 준비 완료라고 표시하지 않는다.

## 그래프·GNN 후속 TODO — 미구현 7단계

### 설명용 시나리오

사용자가 “이 제품에 적용되는 설치 절차의 근거 문서는?”이라고 물었다고 가정한다. 기존 검색이 문서를 찾고, 향후 GNN은 추가 근거 후보를 추천할 수 있다. 다른 제품·개정본·미승인·권한 밖 문서라면 점수가 높아도 답변 근거로 쓰면 안 된다. 제품/매뉴얼은 설명용 예시이며 프로젝트는 범용 RAG로 유지한다. MRO 전용 모델로 바꾸지 않는다.

### 순서·역할·작은 완료 기준

각 단계는 후속 TODO이며 아직 구현하지 않았다. 기존 검색·LLM·평가 계약 이후에 검토하고, 큰 항목은 독립적으로 검토 가능한 크기로 나눈다. 기획 검토와 범위 승인 후 구현을 재개하면 **lexical 매핑 계약을 첫 후보로 유지**하고 날짜를 다시 정한다. GNN은 그 이후의 후속 검토다.

- [ ] **G1. GNN 없는 검색 기반선과 평가 질문 확보.** 기존 검색 결과와 검토된 질문/정답 근거가 비교 기준이다. 현재 합성6case는 입력 계약용이므로 효과 측정에 충분한지 따로 판단한다. **완료 기준:** 작은 질문 집합·문서/권한 snapshot·정답 출처·검색 설정·기준 결과를 기록한다. 아직 기준선을 실행하지 못했다면 그 제약을 남긴다.

- [ ] **G2. 온톨로지와 출처가 있는 KG 설계.** 온톨로지는 개념/관계의 공통 뜻을 정하고, KG는 검증된 관계를 출처와 함께 연결한다. **완료 기준:** 작은 개념/관계 표와 검토된 관계 예시를 만들고 문서 ID·버전·근거 위치·적용 대상/범위·검증 상태를 붙인다. 관찰된 사실과 추정 관계는 분리한다.

- [ ] **G3. GNN 추천 목표와 학습 데이터 계약 정의.** GNN은 그래프의 연결/특성에서 후보 관계를 예측하는 실험이다. 예측 대상을 범용 질문–근거 후보 관계 등 실제 데이터에 맞춰 결정하고, 노드·엣지·특성·정답/음성/미확정 label을 정의한다. 이는 예시이며 확정 아키텍처가 아니다. **완료 기준:** 목표/입출력/label 출처와 train/validation/test 분리 규칙을 한 장으로 정리한다. 동일 문서·개정본·복제 질문의 세트 간 중복과 정답 엣지·미래 문서·평가 정보의 학습 혼입을 막는 검사 예시를 둔다.

- [ ] **G4. 작은 오프라인 학습과 후보 top-K 추론.** 먼저 제한된 데이터로 재현 가능한 학습/추론이 가능한지만 확인한다. 결과는 후보 ID·점수·모델 버전이며 확정 사실이 아니다. **완료 기준:** 데이터/분리 버전·설정·seed와 작은 실행 기록, 질문 한 건의 top-K 후보 출력을 보관한다. Java를 선호하지만 학습 언어·프레임워크·새 설치는 미결정이며 이번 TODO 갱신에서 선택하거나 설치하지 않는다.

- [ ] **G5. Java 포트와 교체 가능한 추론 adapter 계약.** 기존 헥사고날 구조에서 선택적으로 후보를 받는 경계를 검토한다. 예상 흐름은 `질문 → 기존 검색/선택적 GNN 후보 → 후보 정규화 → G6 검증 → 허용 근거만 생성·인용`이다. **완료 기준:** 입력 문맥, 후보 ID/점수/모델·출처 식별 정보, timeout/오류/미사용 동작과 로컬 mock 계약을 정의한다. 실제 DTO·포트 위치와 추론 통신 방식은 그때 결정하며 기존 검색을 무단 교체하지 않는다.

- [ ] **G6. 후보의 적용 대상·문서·승인/권한·인용 검증과 보류.** 추천 점수 대신 현재 문서/정책을 근거로 사용 가능 여부를 판단한다. **완료 기준:** 적용 대상/범위, 현재 버전·삭제 상태, 승인 상태·호출자 권한, 인용 가능한 원문 위치를 대조하는 작은 fixture를 정한다. 검증 불가 시 HOLD(근거 보류) 또는 기존 검색 fallback의 조건을 명시한다. fallback에도 같은 검증을 적용하며 허용 근거가 없으면 답변을 보류한다. HOLD의 실제 응답 계약은 후속 결정이다.

- [ ] **G7. GNN 없는 방식과 비교 후 채택 판단.** 같은 질문·문서/권한 snapshot·예산으로 기존 검색, 규칙/단순 그래프 조회, GNN 후보 방식을 비교한다. **완료 기준:** 근거 품질·인용 정확도·권한/적용 범위 위반·보류 결과와 지연/학습·추론 비용을 기록하고 채택/보류/제외 이유를 남긴다. 학습 데이터·목표·효과가 불충분하면 GNN을 보류할 수 있다.

단순 그래프 조회는 GNN이 아니다. GNN 예측을 검증된 관계와 섞어 KG에 자동 저장하거나 확정 사실로 표시하지 않는다. 별도 교육용 Java GNN 샘플은 설명/실험 참고이며 이 프로젝트의 구현 완료가 아니다. 위 7단계는 계획만 기록한 것이고 코드·학습·설치·외부 호출을 시작한 상태가 아니다.

실제 외부 서비스·데이터·비용 조건이 필요한 항목은 해당 전제를 확인한 뒤 진행한다. 11/02는 테스트 전용 합성 case 로더/계약1건까지만 완료했다. 11/03에는 기획 문서 정합성만 정리했으며 이후 구현 작업과 그래프 기능은 아직 수행하지 않았다.
