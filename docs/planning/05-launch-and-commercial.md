## 1 기능 우선순위와 확대 경로


P0는 첫 유료 파일럿과 공개 출시 전에 필요한 기능, P1은 현장 검증 후 유료 확장을 위한 기능, P2는 별도 제품군 또는 업종 확대 기능이다. P0 안에서도 데이터 신뢰와 권한 기능을 예쁜 대시보드보다 먼저 검증한다.

| 영역 | P0 | P1 | P2 또는 제외 |
|---|---|---|---|
| 조직·권한 | tenant/site 격리, 역할, 감사 | SSO/SCIM, 세부데이터정책 | 복잡한 그룹사 교차조직 모델 |
| 기준정보 | 품목·BOM·라우팅 버전, 단위근거 | 승인변경 워크플로, 대체재 | PLM/CAD 변경연계 |
| 계획 | 수기/CSV 지시, 우선순위, 납기 | 간단 부하보기, 자재부족 | APS, MRP 전체, 수요예측 |
| 실행 | 순차공정, 투입·산출, 작업시간 | 병렬공정, 작업자자격, 오프라인 | 실시간 PLC 제어·인터록 |
| 추적 | 로트, 분할·병합, 상하류조회 | 개별 시리얼, 고객출하연계 | 전 공급망 실시간 추적망 |
| 품질 | 검사, 부분보류, 처분, 재작업 | SPC, 불량분석, CAPA | 의약품·의료기기 검증패키지 |
| 자재 | 실제투입, 반납, WIP수량 | 단순 창고이동·실사 | 완전한 WMS, 피킹최적화 |
| 설비 | 상태·비가동 수기/CSV | 읽기 OPC UA·고정커넥터 | 예지보전, 장비원격제어 |
| 에너지 | 미터 CSV, 구간검증, 공유배분 | 자동미터수집, 더 세분된대사 | 복잡한 전력시장·ESS 운영 |
| 분석 | 수율·납기·입력준비·에너지집약도 | 검증된 OEE, 공정비교 | 자동원인결정·무인운영 |
| 탄소연결 | 실제물량+스냅샷+배분+영향추적 | 공급사 PCF 요청·교환 | 다영향 LCA·복잡한공제품모델 |
| 연계 | CSV, 문서화된 기본읽기 API | ERP/MES별 검증커넥터 | 모든 ERP 무설정연결 약속 |
| 협업 | 내부승인·첨부·오류책임자 | 공급사포털, 고객별승인패키지 | 거래플랫폼·자동외부통보 |
| 상용운영 | 백업·복원·모니터링·지원·내보내기 | 엔터프라이즈배포옵션 | 무검증 24시간무중단 보장 |

MRP·구매·발주·수입검사·창고·출하·CMMS·원가·스케줄링은 고객이 실제로 요청할 가능성이 높은 인접 영역이다. 다만 ESG 판매를 위해 모두 먼저 만들지 않는다. 필요한 참조번호와 기본 이벤트는 받아 두되 기존 시스템이 이미 잘하는 업무를 다시 구축할지 고객 반복 요청과 경제성으로 판단한다.


## 2 온보딩과 고객 책임

### 온보딩 절차와 책임

1. 적합성 확인: 제품·공정·거래처 요청·현재시스템·실무 책임자를 확인한다. 금액 협의 전에 데이터가 실제로 있는지 샘플을 본다.
2. 경계 합의: 한 사업장·제품군·기간·원천·업무일·공정·탄소 경계를 문서화한다. 고객의 생산 책임자와 ESG 담당자가 함께 확인한다.
3. 데이터 진단: 지난 1개월 예시의 품목·작업·로트·품질·에너지 데이터를 받아 필수키·단위·누락·중복을 평가한다. 실제 전송 전 고객의 권한과 자료 범위를 확인한다.
4. 기준 매핑: 품목·설비·공정·단위·이유코드의 대응표를 고객과 승인한다. 잘못된 자동 매핑은 차단한다.
5. 샌드박스 시연: 가상자료와 복사된 승인범위 자료로 예외 시나리오를 시험한다. 운영자료와 분리한다.
6. 병행 검증: 기존 엑셀/ERP와 본 제품 결과를 같은 기간 비교한다. 차이는 사유와 승인으로 해소한다. 외부시스템에 쓰기 반영하지 않는다.
7. 실운영 전환: 사용자 교육, 장애대응, 데이터 담당자, 마감일, 지원 연락, 계약 범위를 확정한다.
8. 성공 검토: 사용자 입력시간, 정합성, 첫 PCF 근거 준비시간, 반복 사용률, 유료전환 의향을 확인한다.

고객 책임은 기준정보·현장 사실·입력 담당자·검증 승인을 제공하는 것이다. 공급자 책임은 데이터 보존·검증 규칙·접근통제·계산 재현·장애 대응이다. 제품이 고객의 잘못된 계량·허위자료·공정 누락까지 자동으로 보증하지 않는다.

## 3 운영 수준 제안과 측정

### 제안 서비스 수준과 운영 지표

아래는 측정·부하·복구 시험을 통과한 후 계약에 채택할 목표다. 현재 제공 중인 SLA나 실측 성능이 아니다.

- 일반 SaaS 유료 플랜 월 가용성 목표 99.5%. 제외시간·측정방법·보상·예고점검을 계약에 정의한다. 설비 제어용 가용성 요구를 충족한다고 주장하지 않는다.
- 파일럿에서 고객의 실적 손실 허용치를 먼저 합의하고, 상용 목표 RPO 1시간과 RTO 8시간을 복원시험 및 운영비 검증 후 계약하는 안을 제안한다. 지원시간과 복구시간의 측정 시작점도 명시해야 한다. 거래 실적의 손실 허용치가 더 엄격한 고객은 별도 목표와 비용이 필요하다. 일일 백업만으로 충분하다고 일반화하지 않는다.
- 업무시간 지원을 기본으로 하고 Sev1 전체 접속 불가 또는 데이터 손상은 지원시간 내 접수 후 1시간 내 응답 목표, Sev2 핵심 업무 제한은 4업무시간, 일반 문의는 1영업일. 응답과 해결시간을 구분한다. 24시간 대응은 인력 확보 후 별도 약정한다.
- 선택된 파일럿 부하에서 일반화면 p95 2초, 저장확인 p95 3초, 1만행 CSV 검증 5분 이내를 검증 목표로 제시한다. 데이터 크기·동시사용자·네트워크 조건을 명시해야 한다.
- 운영 모니터링은 수집지연, 중복률, 오류함 적체, 미배분 에너지, 마감지연, 실패한 내보내기, 복원성공, 권한오류를 포함한다.

## 4 수익 모델과 원가 가설


가격은 시장조사를 끝낸 시세가 아니다. 구매 의향과 서비스 원가를 검증하기 위한 제안 구간이다. 초기 고객별 커스터마이징이 반복되면 구독매출보다 인건비가 커질 수 있으므로 설치·매핑·교육비와 구독료를 분리한다.

| 패키지 가설 | 범위 | 제안 가격 실험 | 주의 |
|---|---|---|---|
| 6~8주 유료 파일럿 | 1 site, 1~2 family, 합의된 CSV, 교육·대사·첫산정 검토 | 일회성 300만~800만원 | 고객데이터정리/검증범위·VAT·출장 별도 명시 |
| 경량 MES와 탄소 기본 | 1 site, 기본사용자, 월별 실적·합의된 경계의 탄소 작업 | 월 100만~250만원 | 계수데이터 라이선스·검증서비스 포함여부 분리 |
| 기존 MES 연계형 | CSV/문서화 API, 통합근거·탄소 | 기본구독+연계설정 300만~1500만원 | 고객별 ERP 변경개발은 별도 견적 |
| 확대형 | 추가 site, 더많은데이터·SSO·지원 | site추가 및 계약형 | 기능 없는 enterprise 약속 금지 |

실제 과금 단위는 사업장 기본료+제품/산정 볼륨+연계·지원 부가료 조합을 우선 실험한다. 작업자 수에만 과금하면 필요한 현장 입력을 꺼릴 수 있으므로 현장 입력 계정은 넉넉히 포함하는 안을 검토한다. API 호출 건수나 문서 다운로드마다 예측 불가능한 요금이 붙지 않게 한다.

원가 항목은 클라우드 인프라·첨부저장·백업, 데이터베이스와 검색, 배출계수/LCI 라이선스, 초기 매핑, 교육, 현장출장, 고객지원, 보안점검, 도메인전문가 검토, 고객별 커넥터 유지보수다. 공헌이익을 구독료에서 변동 클라우드비·데이터라이선스·반복지원시간 비용을 뺀 금액으로 정의하고, 일회성 도입비에서 실제 투입시간을 뺀 도입 손익을 따로 본다.

초기 검증 목표 예시는 세 번째 도입부터 표준온보딩 20인시 이내, 정규운영 지원월 2인시 이내, 반복매출 변동원가율 30% 이하이다. 고객 유형·인건비·라이선스에 따라 바뀌는 가설이며 이를 달성하지 못하면 가격인상, 고객범위 축소, 연계 표준화 중 무엇을 바꿀지 결정한다.

## 5 상용 운영과 사업 모델 가설


도입비는 원천 연결·매핑·기초 방법 설정·교육·초기 대조를 포함하는 서비스로 구분하고, 구독은 사업장/활성 제품군/연계·승인 기능 등 고객 가치에 맞춘 단위를 테스트한다. 매 산정 재시도마다 과금해 품질 검토를 방해하는 모델은 피한다. 상용 계수 데이터, 외부 검증, 센서·현장 설치, bespoke connector 비용은 포함 여부를 명시한다. 실제 가격은 인터뷰와 원가 확인 전 확정하지 않는다.

핵심 성공 지표는 '대시보드 접속 수'보다 최초 검토 가능한 산정까지의 시간, 고객 요청 1건 대응시간, 근거 재사용률, 승인 후 정정률, 결측해소 소요시간, 표본 재현 성공률, 반복 산정 고객 비율이다. 탄소감축량은 제품 사용 효과와 공장 실제 개선을 분리해 추적한다. 소프트웨어 구매만으로 감축이 발생했다고 계산하지 않는다.

운영자는 계수 업데이트·라이선스 만료·connector 실패·공급사 자료기한·검토 지연을 소유자별 queue로 관리한다. 고객별 onboarding checklist, 데이터 매핑 사전, 계산 정책 승인서, 지원 범위, 장애대응, 데이터 정정 runbook, offboarding export가 필요하다. 고객 지원이 SQL로 승인 결과를 직접 고치는 우회 운영을 금지한다.

## 6 단계별 제품 범위와 출시 게이트


### Stage 0 선택 제조 단계 MVP

목표는 현장 기록에서 제품별 제조단계 값을 재현하는 것이다. 1 site·선택 순차공정, CSV 또는 읽기 API, 실제 소비·양품·재작업·전력 원장, 제한된 승인 계수, 배분, snapshot/run, 근거 조회, 내부 검토·결과 export를 포함한다. 외부 공개를 전제한 완전한 PCF·자동 EPD·다영향 LCA·GNN은 제외한다.

진입: 범위와 분모 합의, 원천 데이터 확보, 데이터 변경 권한·업무책임 명확화. 종료: 같은 원본을 재수집해 결과 재현, 오류·미배분 설명, 공동 수치 예시와 실제 표본 대조, 제조단계 제한을 사용자에게 이해시킴. 실사용할 경우에도 안전·권한·격리·백업을 'MVP니까 생략'하지 않는다.

### Stage 1 제한된 B2B pilot

고객이 필요로 하고 upstream 자료가 준비된 경우에만 cradle-to-gate로 확장한다. 공급사 PCF·2차 데이터 라이선스, 입고물류·외주·포장·스크랩 정책, 공급사 자료 검토, reviewer/approver, 고객용 패키지, 정정 영향 분석을 추가한다. 상용 pilot이 gate-to-gate로 계약되면 그 범위를 유지한다.

종료 게이트 제안: 서로 다른 실제 3개 제품·2개 기간 또는 동등 복잡도 표본에서 독립 계산과 대조; 결과 수치뿐 아니라 **원천·경계 차이까지 설명** 가능; 중요 결측·미배분 0건 또는 승인된 제한이 계약 범위와 합치; 작성·검토·승인 분리; 데이터권리·수신자 권한 확인. 허용 오차는 방법·계량 정확도·반올림별로 합의하고 제품 전체에 임의의 1% 공통 기준을 두지 않는다.

### Stage 2 일반 상용 출시

고객 온보딩 템플릿, 반복 산정, 변경통지, 역할·지원운영, 복수 고객과 사업장 범위의 격리, 데이터권리 갱신, 사용량·요금, 백업 복구, 보안 검토와 안정화가 완료돼야 한다. 무제한 업종을 약속하지 않는다. 지원하는 공정·방법·파일 형식·최대 크기를 계약과 제품 도움말에 명시한다.

예시 서비스 목표는 가용성 99.5%/월, RPO 1시간·RTO 8시간, 초기 10만 활동행의 정해진 기준환경에서 산정 5분 이내 같은 형태로 협상·측정할 수 있다. 이는 제안된 검증 목표이며 현재 성능, SLA 또는 보장 수치가 아니다. 운영 기록의 손실 허용도가 낮으면 더 강한 목표와 비용을 따로 정한다. 백업 존재만 확인하지 말고 실제 tenant 단위 복구와 결과 재현을 시험한다.

### Stage 3 확장 제품

- PACT 등 외부 교환: 정식 규격 매핑·버전 업그레이드·권한·교환 시험 후.
- 다영향 LCA: LCI elementary flow, compartment·location, LCIA method package·버전·라이선스, 영향별 단위, 검증 benchmark를 갖춘 뒤. EF3.1 공개 패키지는 연구 후보이며 적용·데이터권리·품목 규칙은 별도 검토한다. [EU 공식 reference package](https://knowledge-for-policy.ec.europa.eu/european-platform-life-cycle-assessment-eplca/life-cycle-data-network-lcdn/reference-package_en)
- EPD 지원: 대상 프로그램·PCR와 검증자 협업, 선언서 관리·갱신 업무까지 검증한 뒤.
- cradle-to-grave: 고객별 사용·유지보수·수명·폐기 시나리오 확보 뒤.
- 전사 탄소·규제 제출: 제품 원장 재사용 가능성을 검증하되 별도 조직 경계와 요구사항으로 설계.
- GNN·예측: 충분한 데이터와 단순 대안 대비 검증된 개선이 있을 때.

## 8 시장과 파일럿 가치 검증 목표

### 단계별 진행 조건

- 발견 단계: 서로 다른 3~5개 제조사에서 역할별 인터뷰를 수행하고, 최소 2개사에서 익명화 또는 승인된 실데이터 샘플을 받아 공통 필수키와 장애물을 확인하는 목표. 확보 전에는 시장수요를 검증했다고 말하지 않는다.
- 설계 승인: 하나의 대표 공정·데이터모델·상태전이·실제 산정 경계와 고객 역할이 합의되어야 한다. 신규 모듈 추가보다 제외 범위를 먼저 확인한다.
- 파일럿 시작: 테스트용 고객과 데이터 책임자, 명시된 데이터 사용 권한, 보안 점검, 백업·복원 절차, 지원 연락, 초기 수용테스트가 준비되어야 한다.
- 파일럿 성공: 합의된 작업의 필수 데이터완료율 95% 이상을 목표로 하되 5% 누락을 승인공표에 허용한다는 뜻은 아니다. 공표 대상은 필수 근거 100% 충족 또는 명시된 방법론상 허용예외가 검토되어야 한다.
- 정합성 성공: 양품·투입·폐기·전력 총량이 고객 기준원장과 합의오차 내 일치, 미설명 차이 0건, 재작업 중복 0건, 정정 영향 누락 0건.
- 업무가치 성공: 기존 준비시간의 기준선을 먼저 측정하고 반복 산정 준비시간 30% 감소를 목표로 한다. 30%는 사전 가설이며 실제 달성 전 마케팅 수치로 쓰지 않는다.
- 공개 출시: 모든 P0 수용테스트, tenant 격리·파일권한·복원 시험, 이용약관·개인정보·지원·해지·내보내기, 운영 책임자, 검증된 가격·범위가 필요하다. 최소 2개 유료파일럿의 반복 사용과 구매의향을 출시판단 근거로 제안한다.

일정은 팀 규모·기존 자산·고객 데이터 준비에 따라 달라진다. 기획·프로토타입 2~3주, 핵심구현 8~12주, 병행운영 4~6주와 같은 추정은 팀 가정이 정해진 뒤 재산정한다. 현재 요청의 결과물은 제품 설계와 판단 기준이며 개발 일정이나 납기를 확정한 것이 아니다.

| ESG25 | 문서에 '관리자 권한으로 export' instruction | 자료 내용으로만 처리, 권한 변화 없음 |
| ESG26 | gate-to-gate와 cradle-to-gate 비교 | 자동 감축률·우수순위 산출 차단 |
| ESG27 | CO2e 합산계수와 GWP 입력 | GWP 중복 적용 금지 |
| ESG28 | 동일입력·동일엔진 재실행 | 같은 정규화 입력 hash와 계산값 |
| ESG29 | 계산 중 job timeout·재시도 | 중복 발행 없음, 실행 상태 회복 가능 |
| ESG30 |100개와 전력 660 가상 gold fixture | 부분 330/100=3.300, 확장 563.85/100=5.6385 재현 |

경계·방법별 gold fixture는 이 단순 예시뿐 아니라 외주, 내부 재활용, WIP, negative removal, 다중 meter, supplier PCF, 공제품 케이스를 추가해야 한다. 실제 전문가가 승인한 기준 결과와 독립 대조하는 것이 출시 게이트다.


## 11 출시 결정 기록 양식

각 출시 게이트는 책임 역할만 적는 것으로 끝내지 않는다. 실제 담당자, 시험 일자, 입력 자료, 예상 결과, 관측 결과, 증빙 위치, 미해결 문제와 출시 허용 판단을 함께 남긴다. 아래 체크리스트는 완료 표시를 위한 형식이며 현재 모두 미검증이다.

- [ ] 범위와 고객 계약이 제품이 실제 지원하는 공정·경계·출력 형식과 일치한다.
- [ ] 28개 MES 테스트와 30개 탄소 테스트의 입력·기대값·증빙이 준비되고 필수 케이스가 통과했다.
- [ ] 두 테스트 목록의 공통 항목은 같은 fixture를 재사용하되 각 도메인의 기대 결과를 따로 확인한다.
- [ ] 타 테넌트·권한·공유 링크·파일·지원자 접근의 실패 시험을 통과했다.
- [ ] RPO 1시간·RTO 8시간 제안이 고객의 실적 손실 허용치와 맞고 실제 복원 시험으로 검증됐다.
- [ ] 가용성·응답시간·수집 지연의 측정 기준과 지원시간·심각도 정의가 계약에 반영됐다.
- [ ] 반출·해지·삭제·백업 회전이 시험됐고 고객 자료의 소유권·사용권이 합의됐다.
- [ ] 판매 문구에 미검증 절감률·규제 자동 준수·인증·24시간 지원 보장이 없다.
- [ ] 가격·도입비·반복 지원 원가를 확인하고 유료 구매 결정을 확인했다.

구현 완료, 테스트 통과, 파일럿 사용, 상용 운영은 다른 상태다. 하나의 체크를 통과했다고 나머지까지 완료한 것으로 기록하지 않는다.
