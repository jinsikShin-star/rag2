# 화면별 상세 설계 작성 표준

[화면 안내·공통 규칙](README.md) · [업무·역할](../01-mes-workflows.md) · [데이터·권한](../02-data-contract-and-security.md)

> 표준 버전: 0.1 · 기준일: 2026-11-03 · 상태: 작성 규칙 제안
> 새 화면 문서에 아래 항목을 채운다. `미정`을 근거 없이 확정값으로 바꾸지 않는다. 작성만으로 구현·검증 완료를 표시하지 않는다. 모든 예시는 가상 자료로 제한한다.

## 1 문서 머리말과 범위

| 항목 | 작성할 내용 |
|---|---|
| 상위 화면 / 뷰 ID | 기존 상위 ID와 목록·상세·대화상자 하위 ID. 신규 ID면 제안임을 표시 |
| 버전·기준일·상태 | 초안 / 업무 검토 / 합의 / 구현 매핑 / 구현·검증 중 현재 상태 |
| 주역할과 사용자 목적 | 누가 어떤 판단/기록을 위해 여는가. 역할명만 나열하지 않음 |
| 모드 / 원천 책임 | 경량 작성 또는 원천 읽기 연계, 데이터 종류별 소유 시스템 |
| 선행 기획 | 업무·데이터·산정·보안 정책의 상대 링크와 충돌 시 기준 문서 |
| 이번 포함 / 후속 | 이번 뷰·액션과 아직 설계하지 않은 탭·모달·영역을 명시 |
| 가정·미결정 | 제안 책임자, 확인할 실제 표본·정책·질문. 사용자 승인 사실과 분리 |

## 2 구체적 시나리오와 실행 순서

하나의 정상 상황과 하나의 예외 상황을 사용자의 말로 쓴다. 예: 담당자가 승인된 기준정보를 찾고, 실제 LOT의 보류 수량을 확인한다. 가상 ID·수량은 예시임을 밝힌다.

| 순서 | 사용자 행동 | 시스템이 보여주는 정보·검사 | 다음 화면 / 중단선 |
|---|---|---|---|
| 1 진입 | 메뉴 또는 대상 링크 선택 | 현재 범위·권한·모드·데이터 기준 시각 | 접근 불가이면 대상 기밀 정보 미표시 |
| 2 조회 | 필터/대상 선택 | 필터 유효성·허용 범위·원천 버전 | 로딩·빈 결과·지연을 구분 |
| 3 판단/입력 | 허용된 행동 선택 | 단위·출처·변경 영향·차단 이유 | 원천 직접 변경 대신 정정 요청 등 |
| 4 제출/확인 | 명시적으로 확정 | 현재 권한·revision·상태·중복 검사 | 성공 결과 또는 충돌/결과 불명 |
| 5 후속 | 결과·이력·다음 업무 이동 | 서버 확정 시각·새 버전·근거·후속 상태 | 별도 승인/발행을 자동 통과하지 않음 |

## 3 레이아웃 와이어프레임

각 목록·상세·주요 입력 대화상자에 별도 와이어프레임을 둔다. 표 안의 각 버튼은 이벤트 ID와 연결하고 장식용 가짜 버튼을 남기지 않는다. 제목/브레드크럼, 범위·원천·모드·상태·신선도, 주행동/차단 이유, 표·필터·탭·근거 패널 위치를 표시한다.

```text
+-----------------------------------------------------------------------+
| 조직 / 사업장 / 허용 범위 | 모드 | 원천 | 기준 시각 / 지연               |
| 상위 메뉴 > 대상     화면 제목 [업무 상태] [주행동 E-01]                 |
+-----------------------------------------------------------------------+
| 필터: 필수 조건·단위·기간      [조회 E-02] [초기화 E-03]                 |
+----------------------------------------------+------------------------+
| 목록 또는 기본/수량/근거/이력 탭             | 선택 대상·상태 요약    |
| 필드명 | 값 | 단위 | 원천/버전 | 검증 상태    | 차단 이유·다음 행동    |
| 각 행의 상세 진입 E-04                       | 근거 위치·조회 한계    |
+----------------------------------------------+------------------------+
| 결과/오류 요약  마지막 서버 저장 시각      [취소 E-05] [제출 E-06]       |
+-----------------------------------------------------------------------+
```

위 배치는 작성 예시다. 실제 문서에서는 미사용 버튼을 지우고 해당 화면 이름·필드·이벤트 ID로 바꾼다. 좁은 화면의 축소 방식, 읽기 순서, 키보드 포커스, 모달 닫기/복귀 위치도 적는다. 마우스만 가능한 행 클릭 대신 키보드로 여는 동작을 지정한다.

## 4 역할·진입·조회 계약

| 역할 | 볼 수 있는 범위 | 가능한 행동 | 금지/추가 승인 | 권한 변경 시 동작 |
|---|---|---|---|---|
| 실제 업무 역할로 기입 | tenant/site/product/artifact | 조회·초안·요청·승인 등 각각 | 원천 직접 수정·자기 승인·외부 공유 분리 | 제출 시 서버 재검사와 재인증/접근 불가 처리 |

- 메뉴 진입, 직접 링크, 알림 링크, 뒤로 가기에서 필요한 범위를 각각 적는다.
- 기본 필터·허용 기간·정렬·페이지/전체 건수·선택 유지 범위를 적는다. 수치 제한은 미정이면 미정으로 둔다.
- 검색·다운로드·증빙·계보·감사 패널도 본문과 동일한 권한 범위를 사용한다.
- 원천 지연/누락·조회의 최대 범위·일부 노드 비공개를 완전한 업무 사실로 오해하지 않게 표시한다.

## 5 필드 사전

| 필드 ID / 화면 표시명 | 형식·단위 | 필수 조건 | 원천·버전 / 편집 주체 | 검증·예시 | 저장·표시 의미 |
|---|---|---|---|---|---|
| 화면별 실제 필드 기입 | 문자열/수량/시각, ea·kg·kWh 등 | 항상/상태별/조회 조건 | 원천 key/revision 또는 새 초안 입력 | 공백·범위·단위 변환·유효일 | 원 계량/배분·계획/실제·초안/승인 구분 |

필수 표시는 조회 필터와 업무 저장 필드의 필수를 구분한다. 표시 이름과 내부 식별자, 원천 기준 시각과 수집/서버 저장 시각, 현지 시각·시간대와 UTC를 혼동하지 않는다. 단위 변환은 근거·유효일·버전이 없는 임의 환산을 금지한다. 숫자 반올림·소수 자릿수·음수 허용·빈 값과 0의 구별은 필드별로 적고 미정이면 남긴다.

## 6 상태와 허용 전이

| 상태축 | 이전 → 다음 | 실행 주체·버튼 | 선행조건 / 차단 | 원본·개정·후속 영향 |
|---|---|---|---|---|
| 실제 업무 축 | 예시가 아닌 해당 업무의 상태 | 이벤트 ID 연결 | 권한·현재 revision·증빙 | 불변 승인본 보존·새 revision·후속 검토 |

초안/승인, 생산 흐름, 품질 처분, 수량 버킷, 계산 Run, 외부 공유 상태를 서로 다른 축으로 적는다. `조회 성공`은 업무 승인 전이가 아니다. 기존 기획에 없는 전이는 **제안**으로 표시한다. 원천 정정은 대상 원문을 지우는 UI 동작으로 만들지 않는다.

## 7 버튼별 이벤트 상세

와이어프레임의 모든 버튼·행 액션·탭·폼 제출에 안정적인 이벤트 ID를 붙인다. 아래 표를 **각 이벤트마다** 작성하거나 같은 열이 있는 목록 표로 확장한다. 공통 규칙을 참조하더라도 그 화면의 입력·상태·권한·오류 차이를 생략하지 않는다.

| 계약 항목 | 화면별로 채울 내용 |
|---|---|
| 이벤트 ID / 버튼 표시명 | 화면 ID와 연계. 예: 해당 뷰의 조회/초안 저장/정정 요청 |
| 시작 조건·입력 | 선택 대상·필터·현재 revision·수량/단위·사유·증빙·작업 식별자 |
| 클라이언트·서버 검증 | 필수·타입·단위·상태·버전·수량수지·원천 소유권 |
| 권한 검사 | tenant/site/product/artifact/action 교집합, 승인 분리, 제출 시 재검사 |
| 상태 변화·원자성 | 실제로 바뀌는 대상/새 revision·아직 바뀌지 않는 상태·동시 변경 처리 |
| 성공 | 서버 ID·버전·시각·상태, 메시지·목록 갱신·상세 이동·포커스 |
| 입력/업무 오류 | 필드 오류·차단 사유·입력 보존·다음 행동 |
| 권한/충돌 오류 | 새 권한 확인·존재 누출 방지·최신본 비교·덮어쓰기 금지 |
| 통신/응답 불명 | 조회 실패와 쓰기 결과 불명을 구분, 작업 상태 확인·안전한 대사 경로 |
| 중복·재시도 | 같은 키/같은 입력의 기존 결과, 다른 입력의 키 충돌, 중복 생성/합산/통지 방지 |
| 감사·후속 | 행위자/범위/전후 revision/사유/결과/상관 ID, 영향 검토·독립 승인·후속 상태 |

오류 문구는 사용자의 다음 행동을 포함한다. 저장 중 비활성화는 보조 장치이고 서버 중복 방지를 대신하지 않는다. 성공 응답 전 저장·승인 완료 배지를 표시하지 않는다. 작업 상태 조회 계약·키 유효기간·최종 API 상태 코드는 구현 전 매핑 사항으로 남긴다.

## 8 빈·로딩·실패·충돌·이탈 상태

| 상황 | 표시 | 허용 행동 | 차단/복구 기준 |
|---|---|---|---|
| 최초/필터 조회 로딩 | 현재 범위와 진행 상태 | 안전한 조회 취소·이동 | 이전 범위 응답 무효화 |
| 데이터 없음 / 필터 결과 없음 | 두 원인을 구별 | 권한 있는 생성 안내 / 초기화 | 실패를 0건으로 표시 금지 |
| 일부 패널 실패 | 실패 패널·기준 시각·한계 | 해당 부분 재조회 | 나머지 성공을 전체 성공으로 표시 금지 |
| 오래된 원천 / 비공개 관계 | freshness·조회 제한 | 원천 상태/담당 확인 | 근거 없는 완전성 보장 금지 |
| 권한 회수·세션 만료 | 재인증/접근 안내 | 허용된 재진입 | 기밀 임시 값의 장기 보관 금지 |
| 쓰기 결과 불명 | 확인 중/확인 필요 | 작업 ID 상태 확인 | 새 키로 맹목 재전송 금지 |
| 동시 수정 | 서버 최신본과 내 변경 차이 | 다시 검토·새 의도 제출 | 자동 덮어쓰기 금지 |
| 미저장 이탈 | 명시적인 이탈 확인 | 돌아가기/버리기/허용 초안 저장 | 새로 고침 후 복구 보장 여부는 미결정 |

## 9 수용 기준 — 실행 전 시나리오

화면별로 성공·차단·권한·중복·불명·충돌·접근성의 Given/When/Then을 작성한다. 아래는 작성 틀이며 아직 실행된 테스트가 아니다.

| AC ID | Given(전제) | When(행동) | Then(보이는 결과·불변 조건) | 검증 방법·근거 / 상태 |
|---|---|---|---|---|
| 화면별 고유 ID | 권한·원천·revision·수량 구체 값 | 이벤트 ID | 상태·서버 확인·원본 보존·후속 영향 | 문서 검토 / 향후 UI·API 테스트, 미실행 |

최소한 정상 조회, 권한 없는 직접 진입, 필수/단위 오류, 승인본 변경 시도, 두 사용자 동시 수정, 중복 클릭, 저장 응답 유실, 원천 지연, 부분 조회 실패, 키보드/포커스, 이탈 경고를 검토한다. 화면 특성상 해당하지 않으면 이유를 적는다.

## 10 미결정과 질문

| 결정 ID | 미결정/가정 | 선택이 바꾸는 화면·동작 | 필요한 증거·확인 역할 | 결정 전 처리 |
|---|---|---|---|---|
| 화면별 고유 ID | 고객·산업·단위·승인·원천 정책 등 | 필드/버튼/상태/수용 기준 | 실제 표본·업무 담당자, 담당 배정 미정 | 제안 유지 / 해당 쓰기·승인 범위 보류 |

기존 기획과 충돌하면 표준 문서를 먼저 확인하고 충돌을 기록한다. 편의를 위해 승인 분리·계산 경계·데이터 권리를 바꾸지 않는다.

## 11 UI 개발 시 동기화 표

| 뷰·이벤트 ID | 화면 문서 버전 | UI 라우트·컴포넌트 | API/DTO·권한 계약 | 상태/오류 매핑 | 수용 테스트·실행 근거 | 동기화 상태 |
|---|---|---|---|---|---|---|
| 해당 ID | 0.1 초안 | **미매핑·미구현** | **미매핑** | **미매핑** | **미작성·미실행** | 설계 검토 전 |

기존 Java/Spring RAG demo API를 새 MES/탄소 화면 API로 연결됐다고 쓰지 않는다. UI 구현 단계에서 실제 경로·컴포넌트·계약과 테스트가 생기면 같은 변경 묶음에서 표를 갱신한다. 구현과 문서가 다르면 차이·이유·영향을 남기고 오래된 초안을 합의 완료로 유지하지 않는다.

## 12 변경 이력과 문서 완료 체크

| 버전·날짜 | 변경 이유 | 영향 뷰·이벤트·AC | 실제 검사 | 검토자·미결정 |
|---|---|---|---|---|
| 화면별 작성 | 사용자 요청/업무 오류 등 | 변경한 ID | 실제 실행 결과와 미실행 구분 | 배정 전이면 미정 |
