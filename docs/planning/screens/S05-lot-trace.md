## 1 시나리오와 이번 범위

품질 담당자가 완성 LOT L100의 일부 보류가 어디에 영향을 주는지 찾는다. 생산 담당자는 현재 사용 가능한 수량을 확인하고, ESG 담당자는 선택 스냅샷에 들어간 당시 기록과 이후 정정을 구분한다. 모든 회사·품목·LOT·시각·수량은 가상 설명용이다.

1. S05-L에서 사업장·기준시각·품목·품질 조건으로 조회한다. 현재 보유 수량과 이미 이동한 수량의 의미를 확인한다.
2. L100 행을 열어 S05-D에서 현재 상태, 분할 이력, 부모·자식 계보와 원천을 대조한다.
3. 품질 처분은 S06으로, 잘못된 원천 값은 사유와 근거를 가진 정정요청으로 연결한다. 이 화면에서 보류를 즉시 해제하거나 수량을 직접 바꾸지 않는다.
4. 승인 스냅샷을 선택하면 당시 개정과 기준시각을 고정해서 읽는다. 현재 변경 여부는 별도 표시하며 과거 스냅샷을 갱신하지 않는다.

이번 상세 범위는 **조회·근거 확인·정정요청·후속 업무 이동**이다. 분할·물리적 병합·보류 해제·폐기 실행 폼, 출하·회수 실행, 계산·승인은 후속 설계다. 실제 출하가 외부 ERP에만 있으면 마지막 확인된 참조와 조회 한계를 표시한다.

### 수량을 읽는 예

| 시점 | 현재 물리 상태 | 이 화면의 합계 | 합계에 다시 넣지 않는 기록 |
|---|---|---|---|
| T0 생성 직후 | L100 100 ea | 현재 보유 100 ea | 없음 |
| T1 부분 보류 분할 후 | L100 잔량 80 ea 가용, 자식 L100-H 20 ea 보류 | 같은 시점의 가용 80 + 보류 20 = 100 ea | L100의 **생성 당시 100 ea**와 분할 이동 20 ea |
| T2 품질 처분 후 | L100 80 ea 가용, L100-H의 15 ea 적합·5 ea 폐기 | 현재 가용 95 + 폐기 5 = 원래 100 ea | T1 보류 20과 T2 처분 20을 중복 가산하지 않음 |

목록과 상세는 기본으로 T1을 보여주는 가상 예다. T2는 후속 S06 처분 결과를 설명한다. 가용·보류·폐기는 상호 배타적인 물리 수량 구간이며, 원래 생성량·이동량·공정 통과량은 다른 지표다. ea와 kg는 품목 개정·유효기간·근거가 있는 환산 없이는 합치거나 변환하지 않는다. 수량수지 일치가 탄소 정확성·출하 가능성 인증을 뜻하지 않는다.

## 2 역할·범위와 원천 모드

| 역할 | 허용할 행동 제안 | 제한 |
|---|---|---|
| 생산 관리자·배정된 생산 담당자 | 허용 LOT 조회, 원천 오류 정정요청 | 확정 원장 직접 수정·품질 보류 해제 불가 |
| 품질 검사자·승인자 | 검사·보류 및 계보 조회, S06 이동 | 여기서 처분 승인하지 않음. S06에서 별도 역할·정책 검사 |
| ESG 분석가·검토자 | 허용 제품/스냅샷의 근거·영향 조회, 정정요청 전달 | 생산 사실 수정·계수 변경·결과 승인 불가 |
| 제한 열람자·외부 검증인 | 명시적으로 허용된 제품·기간·자료 읽기 | 기본 전체 LOT 검색·계보·내보내기 권한 없음 |

tenant ∩ site ∩ 제품/LOT 범위 ∩ artifact ∩ action을 서버에서 판정한다. 버튼 숨김은 보조 표시다. 목록·합계·계보·원천·첨부·감사·다운로드와 비동기 작업에 같은 범위를 적용한다. 허용되지 않은 LOT의 존재·수량·노드 수를 오류나 합계로 추정할 수 없게 한다.

- **경량 모드:** 승인된 책임표에 따라 본 제품이 원천일 수 있다. 그래도 확정 이벤트는 덮어쓰지 않고 정정요청을 거친다.
- **기존 MES 읽기 연계:** authoritative 원천은 읽기 전용이다. 정정은 원천 담당자 요청 또는 승인된 보정 절차로 연결하고 같은 사건의 이중 정정을 방지한다.
- 원천별 최근 수신 시각·원천 기록 시각·지연 표시를 함께 제공한다. 성공적으로 조회했다고 최신 실제 재고가 확인된 것은 아니다.
- 당시 스냅샷 재현과 현재 권한은 별개다. 과거 승인 근거라도 지금 접근권한이 없으면 열람·다운로드하지 못한다.

```text
+--------------------------------------------------------------------------------------------------+
| [메뉴: 로트·품질 > LOT] 조직: 가상조직 / 사업장: A  모드: 기존 MES 읽기 연계 [범위 설정 E01]          |
| LOT 목록                         기준: T1  원천 수신: T1-2분  [지연 경고/출처 설명]                  |
| LOT번호 [L100     ] 품목 [전체 v] 위치 [전체 v] 품질 [전체 v] 흐름 [전체 v]                           |
| 발생기간 [시작 ~ 종료] 기준시각 [T1]  [조회 E01] [초기화 E02]                                       |
| 가용 80 ea | 보류 20 ea | 조회된 현재 보유100 ea   (권한/조회 범위 내, 다른 단위 합산 안함)            |
| [허용 목록 내보내기 E05]   범위: 현재 조건·허용 필드 / 행수는 서버 확인                               |
| 내보내기 작업: 진행/완료/실패  [작업 상태 E21] [결과 다운로드 E22: 완료 시 활성]                       |
| LOT번호 E04 | 품목/rev | 위치 | 현재보유 | 가용 | 품질별 구간 | 흐름 | 원천/신선도 | 현재개정           |
| L100        | A/r3     | FG-A | 80 ea    | 80 ea| 적합80      | 완성 | MES/지연없음| r2                 |
| L100-H      | A/r3     | QA-H | 20 ea    | 0 ea | 보류20      | 완성 | MES/지연없음| r1                 |
| [정렬/이전/다음/페이지 크기 E03]  조회2행 / 기준시각 T1 / 생성이력100+자식20 합산 금지                 |
| 상태영역: 로딩 / 결과 없음 / 일부 출처 지연 / 권한 범위 / 재시도 가능한 오류                         |

```

‘범위 설정’은 권한을 부여하는 기능이 아니다. 선택 가능한 허용 사업장만 제시하며 변경 시 조건·선택 LOT를 비우고 재조회한다. 필터는 명시적 조회 시 적용하고 정렬/페이지는 같은 조회 기준을 유지하는 제안이다. 합계는 서버가 같은 기준시각·권한·중복 제거 규칙으로 산출할 때만 표시하고, 불가능하면 `합계 미산출`로 둔다.

| 필드/열 | 필수·단위 | 원천/검증 | 사용자 편집 |
|---|---|---|---|
| 조직·사업장·모드 | 범위 필수, 단위 없음 | 세션 권한·사업장 원천 책임표 | 허용 범위 선택만 가능 |
| LOT 표시번호·내부 식별자 | 내부 ID 필수 | 표시번호만으로 전역 식별 금지; source+외부키+tenant/site 확인 | 검색 조건만 입력 |
| 품목·revision | LOT마다 필수 | 기록 당시 품목 개정과 연결; 현재 마스터로 치환하지 않음 | 필터만 선택 |
| 위치·흐름·품질 | 값 없으면 미확인 표시 | 위치, 흐름, 품질 처분을 서로 다른 축으로 표시 | 필터만 선택 |
| 현재 보유/가용/버킷 | 수량+원단위 필수 | 기준시각·개정·버킷 정의 표시; 결측을 0으로 보이지 않음 | 읽기 전용 |
| 발생기간·기준시각 | 조회 조건 필수 제안 | 사업장 시간대 표시, [시작, 종료), 시작≤종료; 조회 상한은 미결정 | 조건만 입력 |
| 원천/수신 시각·상태 | 출처 필수, 시각은 보유 시 | source revision·지연·수집 실패 구별 | 읽기 전용 |

## 4 S05-D LOT 상세·계보

### 배치와 영역의 역할

```text
+--------------------------------------------------------------------------------------------------+
| [목록으로 E20] 로트·품질 > LOT > L100 조직/사업장 A   기존 MES 읽기 연계   현재 r2 / T1                |
| L100 / 품목 A r3  위치 FG-A | 흐름: 완성 | 품질: 적합80 | 가용80 ea [현재 다시 조회 E06]              |
| 원생성100 ea / 분할이관20 ea / 현재보유80 ea  [당시 스냅샷 E17]  현재 원천 변경: 없음/있음             |
| [기본·수량] [계보] [원천·변환] [품질] [스냅샷·영향] [증빙·감사] E07                               |
| 선택 탭: 계보  기준: 현재 T1  방향[상류/하류 E08]  범위[허용 1단계 v E09] [허용 범위 확장 E09]        |
| 원료 R10 --[투입/작업 W100]--> L100(생성100,現80) --[분할20]--> L100-H(보류20)                      |
| [노드/이벤트 원문 E11] [분할·병합 이력 E16]  조회 범위: 사업장A·제품A·T1 / 일부 연계 미확인            |
| 하단: 현재 잔량80 + 자식20 = 100 ea / 포장 묶음과 물리 병합 구별 / 외부출하 이력 범위 제한            |
| [증빙 열기 E10] [정정요청 작성 E12] [S06 품질 검토로 E15] [산정 영향 조회 E18] [감사 기록 E19]         |
| 내보내기 E05: 선택 LOT·기준시각·허용 노드/필드만 [작업 상태 E21] [결과 다운로드 E22: 완료 시 활성]    |
| 정정요청 패널(열었을 때): 대상event/rev·변경전(고정)·제안값/단위·사유*·근거·영향 검토                |
|                          [요청 제출 E13] [작성 취소 E14]  저장 확인 전에는 제출 완료 배지 없음        |
```

수량 탭은 현재 보유·현재 버킷과 생성/투입/이동 누적 이력을 분리한다. 계보 탭은 시각·변환 이벤트별 연결을 펼쳐 같은 실물을 두 번 세지 않게 한다. 실제 재작업 순환은 새 실행/사건으로 표현하며 자기 조상 상태를 재소비해 수량이 생성되는 잘못된 연결은 오류로 표시한다. 포장 집합의 자식 정체성을 제조 병합으로 바꾸지 않는다.

품질 탭은 검사 범위·표본·보류 구간·처분 승인 참조를 읽는다. 스냅샷 탭은 당시 이벤트 개정과 현재 변경 표시를 나란히 제공한다. 영향 결과는 `조회된 영향 후보`이며 전체 영향·고객 통보·재계산·PCF 승인 완료를 의미하지 않는다.

| 필드/패널 | 필수·단위 | 원천/검증 | 편집 가능 범위 |
|---|---|---|---|
| LOT ID·품목/rev·원천/rev | 대상 선택에 필수 | 불변 내부 ID 및 source 대응 확인 | 읽기 전용 |
| 기준시각·조회 revision·스냅샷 ID | 읽기 문맥 필수 | 현재 조회와 승인 스냅샷 모드를 구별 | 조회 모드만 선택 |
| 부모/자식·변환 ID·수량·유형 | 연결마다 필수 | 분할 부모잔량+자식, 병합 부모별 기여·시각·단위; 누락은 미확인 | 읽기 전용 |
| 품질 처분·구간·위치·흐름 | 각각 따로 보유 | 보류 수량을 가용으로 표시하지 않음; 미처분과 폐기를 구별 | 읽기 전용, S06 참조 |
| 원천 사건·작업·근거·이전 개정 | 있으면 안전한 참조 | 원문 권한·파일 상태·현재 접근범위 재검사 | 읽기 전용 |
| 정정 대상/변경 전 | 제출 시 필수 | 대상 event ID+revision을 고정, 최초 열람값을 서버와 대조 | 변경 전 편집 불가 |
| 정정 제안값·단위·사유 | 요청 시 필수 제안 | 원천별 정정 가능 필드·범위 검증; ea↔kg 무근거 변환 금지 | 요청 패널만; 원장값 변경 아님 |
| 정정 근거·예상 영향 | 정책상 필요 시 필수 | 허용 증빙 ID, 영향 대상/기간과 미확인 항목 구분 | 참조 선택/사유 작성; 첨부 신규 업로드는 별도 설계 |

## 5 버튼·이벤트 계약

아래 E번호의 전체 ID는 `S05-E번호`다. 실제 API route·DTO·저장소·HTTP 오류 코드를 확정한 표가 아니다. 같은 화면에서 역할이 없는 행동은 숨기거나 사유를 설명해 비활성화하되 서버 검사를 생략하지 않는다.

### 모든 이벤트에 적용하는 처리 순서

1. 입력과 선택 문맥(tenant/site, LOT/사건 ID, 기준시각, revision)을 수집하고 형식·필수·단위를 검사한다.
2. 서버가 현재 사용자·행동·제품/LOT·artifact 범위를 다시 검사한다. ID를 바꾸거나 오래된 탭을 써도 범위가 넓어지지 않는다.
3. 조회는 지정 문맥의 결과만 반환한다. 요청 생성은 대상 revision과 원천 책임을 검사한 뒤 요청 상태만 바꾼다. 원장·스냅샷·품질 처분은 그대로다.
4. 성공 응답과 요청/작업 ID를 받은 뒤 완료를 표시한다. 필드 오류는 해당 입력, 업무 충돌은 이유와 허용 다음 행동, 권한 거부는 안전한 메시지로 돌려준다.
5. 중복 제출은 제안한 동일 멱등 키·같은 내용이면 같은 요청/작업을 돌려주며, 같은 키의 다른 내용은 충돌로 처리한다. 키 범위·보존기간은 후속 계약이다.
6. 시간초과 후 **결과 불명**은 새 요청 자동 재생성 대신 E21로 상태를 확인한다. 확인되기 전 `저장됨`으로 표시하지 않고 입력을 보존한다. 권한 철회 때는 민감 입력·화면 캐시 처리 정책도 적용한다.
7. 감사에는 최소한의 actor·범위·action·대상/revision·요청/작업 ID·결과·시각을 남기는 제안이다. 민감 원문·증빙 내용·검색어를 무조건 로그에 복제하지 않는다.

## 6 화면 상태·복구와 접근성

| 상태 | 화면 표시·허용 다음 행동 |
|---|---|
| 첫 진입·조회 중 | 고정된 열 헤더와 로딩 문구, 중복 제출 비활성. 이전 데이터가 있으면 현재 조회 결과로 오인하지 않게 `이전 기준` 표시 |

| 권한 없음/세션 만료 | 안전한 안내와 재인증/관리자 확인 경로. 상세·첨부·캐시를 계속 노출하지 않음; 권한 회복 전 요청 재전송 금지 |
| 일부 출처 지연·일부 탭 실패 | 성공한 영역과 실패한 영역을 나눠 기준시각·재시도 제시. 누락을 0/계보 없음/조회 완료로 표시하지 않음 |
| 수량/계보 모순 | 해당 노드·버킷·원천 참조와 미확인 이유 표시. 보류/정정 검토로 연결하고 자동 수량 보정 금지 |
| stale revision·다중 탭 충돌 | 사용자가 본 값과 현재 개정 차이, 입력 보존·다시 검토 제공. 최신 원장에 요청을 자동 덮어쓰지 않음 |

레이블에 필수 여부와 단위를 글자로 표시하고 색상만으로 보류/오류를 구분하지 않는다. 테이블 열 헤더·정렬 상태, 노드 연결 방향·이벤트명·단위의 텍스트 대안을 제공한다. 키보드로 행 열기·탭·계보 노드·패널 버튼에 접근하고, 패널을 닫으면 이전 트리거로 포커스를 돌린다. 오류 요약에서 해당 필드로 이동하며 조회 완료/결과 불명은 보조기술에도 알린다. 모바일에서는 핵심 LOT·가용·품질·기준시각을 먼저 보여주고 복잡한 계보는 접근 가능한 목록으로 전환하는 제안이며 모바일 UI는 아직 설계/구현하지 않았다.

| AC-L06 | 제출 후 응답이 끊겼을 때 / 같은 키로 상태 확인 / 같은 요청 ID 또는 결과 불명을 돌려주고 원장 변경·요청 중복 생성·성공 오표시가 없다 |
| AC-L07 | 화면을 연 뒤 증빙 권한이 철회됐을 때 / 미리보기·다운로드·완료 job 접근 / 서버가 재검사하고 원문을 반환하지 않는다 |
| AC-L08 | 기존 MES 읽기 모드의 보류 LOT일 때 / 품질 검토·정정요청 버튼 선택 / 원천 직접수정·보류해제·출하/회수/PCF 승인을 실행하지 않는다 |
| AC-L09 | 계보 한 출처가 지연되고 kg와 ea가 섞였을 때 / 조회 / 부분·미확인·원단위를 보여주고 무근거 환산/전체완료 배지를 만들지 않는다 |
| AC-L10 | 키보드만 사용하는 검토자일 때 / 필터→행→계보→패널 오류→닫기 / 이름·단위·관계 대안과 오류 포커스·복귀 포커스를 확인할 수 있다 |

## 8 미결정·작은 다음 작업·구현 동기화

- [ ] 실제 공장 표본에서 표시 LOT번호의 충돌, 단위, 위치/품질 버킷과 기준시각 계산법을 확인한다.
- [ ] 정정요청 가능한 원천별 필드·증빙 요건·검토자·겸직 예외·마감 후 검토 정책을 합의한다. 기존 권고를 새로운 강제 승인 정책으로 승격하지 않는다.
- [ ] 조회 범위/깊이·페이지·export 상한, 비동기 job 필요 여부, 멱등 키 범위/보존·권한 철회·입력 임시보관 정책을 정한다. 용량·응답시간/SLA 수치는 미확정이다.
- [ ] 외부 ERP 출하·공급사 상류·권한 제한 계보에서 공개 가능한 범위 표시와 근거 보존/소실 시 안내를 확인한다.
- [ ] 다음 화면 묶음 후보인 S06 검사·품질 보류에서 검사 결과 입력과 처분 승인을 분리해 설계한다. 분할/병합·재작업/폐기는 해당 선행 업무 설계 후 연결한다.
