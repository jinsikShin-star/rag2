> 버전 0.1 · 기준일 2026-11-04 · **화면 기획 초안 / 업무 사용자 검토 전**
> S06-L 목록과 S06-D 상세·처분 검토의 2개 뷰다. UI·API·권한·감사·사용 차단을 구현하거나 시험한 결과가 아니다. 세부 상태명·버튼 정책은 제안이며 모든 조직·품목·LOT·검사·수량은 가상이다.

## 1 시나리오와 실행 순서

품질 검사자는 가상 LOT L100-H의 재검 기록을 찾고 검사기준 개정과 표본 범위를 확인한다. 검사 결과를 저장·제출한 뒤 품질 승인자는 별도 보류/처분 요청을 검토한다. 생산 담당자는 무엇이 승인됐는지뿐 아니라 원천 시스템에서 해당 수량의 보류·해제·폐기 반영이 확인됐는지 구분한다.

1. 사업장·원천 모드·기준시각을 확인하고 S06-L에서 검사와 미결 보류/처분 건을 조회한다.
2. S06-D에서 검사 대상·표본/모수·기준 개정·원문을 확인한다. 자체 소유 초안만 입력하고 외부 원천은 읽기와 정정 요청으로 제한한다.
3. 검사 결과 제출·확정과 보류/처분 요청·승인을 분리한다. 표본의 불합격 비율을 전체 LOT의 폐기량으로 자동 환산하지 않는다.
4. 승인 후에도 원천 반영 상태를 확인한다. 사용 차단·해제·물리 처분이 확인되지 않으면 실제 적용 완료로 표시하지 않는다.
5. LOT 계보에서 현재 수량과 당시 스냅샷을 대조한다. 품질 승인은 운영 마감·탄소 승인·출하·고객 발행이 아니다.

**이번 범위:** 검사/보류 업무 조회, 자체 검사 초안·결과 검토, 보류/처분 요청과 승인 계약, 근거·이력·원천 반영 확인의 문서 설계다. **후속:** 실제 분할/병합, 재작업·폐기 실행(S07), 외부 QMS/MES 명령·커넥터, 출하/회수, 대량 등록·export, 모바일 전용 입력이다. 버튼 설계가 해당 기능의 구현 착수 승인을 뜻하지 않는다.

### S05와 함께 읽을 수량·검사 예

| 문맥 | 확인된 가상 사실 / 표시 | 여기서 추정하면 안 되는 것 |
|---|---|---|
| T1 물리 수량 | 원래 생성 100 ea에서 L100 잔량 80 ea 가용, 자식 L100-H 20 ea 보류. 현재 가용80+보류20=100 ea | 원 생성100과 자식20을 다시 더하지 않음 |
| T1 검사 Q100 r1 | L100-H 20 ea 중 표본5 ea, 표본 적합3·부적합2. 전체20의 재검은 아직 미완료 | 전체20의 적합12·부적합8로 비례 확대하거나 전량 검사 완료로 표시하지 않음 |
| T1 처분 요청 D100 | 별도 `재검 20 ea` 요청 검토 중. 보류20의 근거는 확인된 원천 보류 사건이며 Q100의 표본 비율이 아님 | 요청 저장/승인만으로 보류 해제·수량 이동 완료를 표시하지 않음 |
| T2 후속 결과 | 별도 Q101의 20 ea 전수 재검과 처분 승인·원천 반영이 확인됐다는 가정에서 자식15 적합·5 폐기. 전체 가용95+폐기5=100 ea | 회복15를 신규 생산으로 더하거나 T1보류20·T2처분20을 함께 합산하지 않음 |

위치·생산 흐름·품질 처분·가용수량은 독립 축이다. ea와 kg는 근거·품목 개정·유효일이 있는 환산 없이는 변환하지 않는다. T1 화면에 T2 결과를 미리 표시하지 않으며, 과거 승인 스냅샷은 당시 사건 개정을 유지한다.

## 2 역할·진입·원천 책임

| 역할 | 허용할 행동 제안 | 제한·추가 조건 |
|---|---|---|
| 품질 검사자 | 배정된 검사 초안·측정값·증빙 참조·검사 제출·보류 제안 | 자신의 부적합 처분을 단독 승인하는 권한을 자동 부여하지 않음 |
| 지정 품질 검토/승인자 | 검사 확인·반려, 허용 수량의 보류/해제/재검/재작업/폐기/조건부 사용 판단 | 원천 값 직접 수정·설비 명령·탄소 승인 불가; 위임·겸직 정책 확인 |
| 생산 담당자 | 허용 LOT·보류 범위·반영 상태 읽기, 원천 오류 정정 요청 | 검사 읽기 권한이 처분 승인 권한을 뜻하지 않음 |
| ESG·제한 열람자 | 허용 제품/기간의 확정 기록·스냅샷 근거 읽기 | 검사 초안·기밀 증빙·전체 품질 원장 접근을 자동 허용하지 않음 |

tenant ∩ site ∩ product/LOT ∩ artifact ∩ action을 서버에서 매번 검사한다. 직접 링크·증빙·감사·operation 조회에도 같은 제한을 적용하며 권한 밖 검사·수량·요청의 존재를 누출하지 않는다. 메뉴, S05의 품질 이동, 알림에서 진입할 수 있지만 알림 수신 자체는 권한이 아니다.

- **경량 작성:** 책임표에서 본 제품이 소유한 검사 초안만 편집한다. 확정 검사·보류 사건은 새 개정/정정으로 연결한다.
- **기존 QMS/MES 연계:** 품질 원천은 읽기 전용이다. 보완 필드와 원천 정정 요청을 구분하고 원천의 승인·적용을 로컬 승인으로 대체하지 않는다.
- 01의 품질 역할 제한과 02의 통합 승인 제안을 함께 적용한다. 내부 겸직·마감 후 검토·예외의 실제 고객 정책과 위임은 미결정이며, 미합의 상태에서 경고만 닫아 처분 승인하도록 설계하지 않는다. 고객 공식 발행은 별도 승인 분리 영역이다.

## 3 S06-L 검사·보류 목록 와이어프레임

```text
+--------------------------------------------------------------------------------------------------+
| 로트·품질 > 검사·보류 | 가상조직 / 사업장 A [범위 E01] | 기존 MES 읽기 연계 | 조회 T1 / 수신 T1-2분 |
| 검사유형 [전체 v] LOT [L100-H ] 품목 [전체 v] 담당 [허용 범위 v] 상태 [전체 v] 기간 [시작~종료] E01 |
| [조회 E01] [초기화 E02]  [신규 검사 초안 E05]  필터·합계는 허용 범위/같은 기준시각만                |
+--------------------------------------------------------------------------------------------------+
| 검사/요청 E04 | LOT·품목rev | 검사 범위       | 검사 상태 | 보류/처분 | 원천 반영       | 담당        |
| Q100 r1      | L100-H/A r3 | 표본5 / 모수20ea| 확정      | D100검토중| 보류20 적용확인 | 품질 담당   |
| D100 r1      | L100-H/A r3 | 재검요청20 ea   | 관련 Q100 | 검토 중   | 처분 미반영     | 품질 승인자 |
| 동일 LOT의 검사·요청은 서로 다른 기록. 두 행의20 ea를 합산한 '보류40'을 표시하지 않음                |
| [정렬/이전/다음/페이지크기 E03]  조회2건(검사1·요청1) / 선택 대상 한 건 / 전체 재고 합계 아님         |
| 빈 결과 / 로딩 / 일부 원천 지연 / 접근 제한 / 실패 패널                     [처리 상태 E24]          |
+--------------------------------------------------------------------------------------------------+
```

목록의 한 행은 `기록 종류 + 불변 ID + revision`이다. 검사와 요청의 건수를 분리하고 같은 LOT 수량을 행 수만큼 집계하지 않는다. E04는 행 선택과 상세 진입을 겸하되 키보드로 여는 명시적 링크를 제공한다. 필터는 E01로 확정하고 정렬/페이지는 확정 조건을 유지한다. 권한 범위 변경 때 이전 결과·선택·지연 응답을 무효화한다.

## 4 S06-D 검사 상세·처분 검토 와이어프레임

```text
+--------------------------------------------------------------------------------------------------+
| [목록으로 E06] 로트·품질 > 검사·보류 > Q100 r1 | 가상조직 / A / 기존 MES 읽기 연계 / 현재 T1         |
| LOT L100-H 20 ea 보류 | 위치 QA-H | 흐름 완성 | 가용0 ea | [LOT·계보 E22] [현재 확인 E08]           |
| 검사: 확정 / 보류: 원천 적용확인 / 처분 D100: 검토중 / 처분 원천반영: 미반영 (서로 다른 상태)         |
| [검사·측정] [보류·처분] [원천·증빙] [승인·감사] 탭 E07  [당시 스냅샷 E27]                          |
+--------------------------------------------------------------------------------------------------+
| 검사 Q100 r1 / 공정 재검 / 기준 QC-r3 [기준·품목 E26] / 표본5ea·모수20ea / 표본 부적합2ea           |
| 항목: 길이 [측정값___ mm] 규격/허용오차: 기준rev참조 / 검사시각·시간대 / 검사자 / 근거*              |
| [초안 편집 E09] [검사 저장 E10] [검사 제출 E11] [검사 확정 E12] [검사 반려 E13] [새 개정 E14]        |
| 확정·외부 원천 필드는 잠금. 오류 발견 시 [원천 정정요청 E28]  근거 [미리보기 E20] [다운로드 E21]     |
| 정정 요청 패널(E28): 원천event/rev·변경 전(고정)·변경 제안/단위·사유·근거 / 원본 저장과 분리         |
+--------------------------------------------------------------------------------------------------+
| 보류·처분 요청 D100 r1: 재검20ea / 대상구간 L100-H 전체20 / 변경 전 고정 / 사유·근거 / 반영상태 미반영 |
| [요청 작성·종류선택 E15] 허용종류: 보류/해제/재검/재작업/폐기/조건부사용 (정책에 따라 제한)             |
| 조건부사용: 대상·용도·유효기간·조건·필요 고객승인 근거; 미확정이면 승인 보류                           |
| [요청 저장 E16] [검토 요청 E17] [처분 승인 E18] [반려 E19]  승인 != 물리 실행/원천 반영 완료          |
| 배너: 보류 요청만 있고 적용 미확인이라면 '사용 차단 확인 필요'; 다음 공정 확정 판단을 보류            |
+--------------------------------------------------------------------------------------------------+
| [변경 취소 E25] [처리 상태 확인 E24] [이력 E23] | 마지막 서버 확인시각 / 입력 변경 / 결과 확인 필요   |
+--------------------------------------------------------------------------------------------------+
```

요약은 현재 물리 상태와 검사/요청/반영 상태를 구별한다. 검사 탭은 무엇을 얼마나 측정했는지, 처분 탭은 어떤 수량에 어떤 결정을 요청했는지 보여준다. 원천 탭은 기록 소유권·지연·정정 연결을, 감사 탭은 판단 근거와 당시 버전을 보여준다. 승인본에서는 편집·저장·재제출을 잠그고 사유를 표시한다. 탭의 미저장 입력은 이탈 전 확인한다.

보류 제안이 긴급하더라도 **요청 중 = 실제 사용 차단 완료**로 표시하지 않는다. 원천 적용 미확인 배너와 조치 담당 경로를 제공하고, 해당 범위의 다음 공정·소비·출하 준비 확정 판단은 보류한다는 원칙을 제안한다. 즉시 보류의 적용 주체·현장 임시조치·원천 확인 방법은 고객 품질 절차와 책임표로 정해야 하며 이 UI가 설비 안전을 보장하지 않는다. 이미 발생한 물리 사실을 숨기지 않고 예외로 기록하는 기존 원칙을 유지한다.

## 5 필드·단위·필수와 편집 경계

| 필드 | 필수 시점 / 형식·단위 | 원천·검증 | 편집 가능 범위 |
|---|---|---|---|
| tenant/site, 검사·요청 불변 ID, revision | 모든 조회/쓰기, 식별자 | 표시번호와 분리, 현재 범위·기대 버전 확인 | 서버 문맥, 임의 변경 불가 |
| 검사 유형·대상 LOT/구간·품목 개정 | 초안 저장, 입고/공정/최종·ID·ea 등 | LOT 당시 품목rev, 남은 대상구간, 중복/중첩 검사 | 자체 소유 작성 중만 |
| 검사기준 ID/rev·측정 항목 | 검사 제출, 불변 참조 | 작업 배포/검사계획에 고정된 기준, 승인·적용일 확인 | 초안 선택; 새 기준으로 기존 확정값 치환 금지 |
| 대상 모수·표본 수·검사 방식 | 제출, 수량+원단위·전수/표본 | 0<표본≤모수, 단위 일치; 파괴검사·질량 샘플 방식은 별도 정책 | 자체 초안; 불명 모수는 미확인·제출 보류 |
| 측정값·규격 상하한·허용오차 | 항목별 제출, mm/kg/판정코드 등 | 기준rev에서 규격 읽기, 숫자·차원·미측정과0 구별; 원값 보존 | 측정값만 초안 입력; 규격은 이 화면에서 수정 불가 |
| 표본 적합/부적합/미판정 수·결과 | 검사 제출, 원단위·결과코드 | 버킷 합=실제 검사표본, 모수 전체 판정과 분리 | 초안 입력/계산 제안, 자동 LOT 처분 금지 |
| 검사 발생시각·시간대·검사자 | 검사 제출, 현지시각+UTC 대응·담당 ID | 원천 발생/수신/저장시각 분리, 배정·위임 확인 | 자체 기록 초안, 임의 과거확정 변경 불가 |
| 근거 ID/rev·재검 원기록 | 정책상 필수 또는 재검 제출 | artifact 권리·검사/격리 상태, 이전 검사·대상 연결 | 허용 참조 선택; 신규 파일 업로드는 이번 범위 밖 |
| 요청 종류·대상구간·수량·단위 | 요청 저장/제출 | 현재 유효 구간과 중첩·이미 소비/처분 여부, 근거 없는 환산 금지 | 자체 요청 초안, 물리 원장 변경 아님 |
| 처분 사유·원인코드·변경 전후·근거 | 검토 요청/승인 | 보류→선택 처분의 의미, 미정 원인은 미분류; 필수 사유 확인 | 해당 역할, 승인 후 불변 |
| 조건부 범위·용도·유효기간·조건·고객 승인 | 조건부 사용 검토 시 | 종료/만료·대상 제한·필요 증빙, 미정책이면 승인 차단 | 요청 초안만; 고객 요구/정책은 미결정 |
| 원천 사건·source revision·반영상태·확인시각 | 연계/적용 표시 | 같은 source ID/rev 중복과 내용 충돌 구분 | 원천 읽기 전용, 확인 불가를 완료로 바꾸지 않음 |
| 작성/검토/승인자·결정시각·operation 참조 | 해당 처리·감사 | action 위임·현재 권한·동일 요청 판정 | 서버 기록, 사용자가 감사 수정/삭제 불가 |

표시 정밀도·단위별 허용오차·표본 채취 방법·불합격 판정 규칙은 기준 개정과 고객 정책으로 확인한다. 입력 편의를 위해 표본 결과를 모수에 복제하거나 미측정 값을 0으로 채우지 않는다. 여러 처분 구간을 쓰려면 합계·상호배타·부분 승인 규칙이 필요하며 이번 초안은 **한 요청·한 대상구간·한 처분 종류**를 기본 제안으로 둔다. T2의 15/5는 후속 두 처분 기록의 반영 결과 예시다.

**승인 계획량과 실제 이동량을 분리한다.** 서버 승인 시 같은 LOT의 식별 가능한 실물/수량 구간·기대 revision·현재 미처분 대상과, 이미 승인됐지만 원천 반영/실행이 대기 중인 대상·수량도 함께 검사한다. 반영 대기 계획을 무시해 같은 20 ea를 두 번 승인하거나 잔량을 초과 소진하지 못한다. 계획상 미배정 잔량은 승인 완료·반영 대기분을 제외해 판단하되 물리 버킷을 미리 줄이지 않는다. 구간 식별·동시 승인 원자성·예약/해제의 구체 DB 구현은 미결정이며, 처리 취소·실패 시에도 같은 대상을 임의로 재사용하기 전에 계획/원천을 대사한다.

## 6 서로 다른 상태축과 전이 제안

| 상태축 | 전이 / 버튼 | 선행조건·불변 조건 |
|---|---|---|
| 검사 기록 | 작성 중→제출됨(E11)→검토 확정(E12), 제출됨→보완(E13) | 측정·표본·기준·근거 충족; 보완은 이력 보존, 확정본은 새 개정 E14/원천 정정 E28 |
| 보류/처분 요청 | 작성 중(E16)→검토 중(E17)→승인(E18) 또는 반려(E19) | 요청 대상rev·수량·권한·사유·근거·승인 분리; 요청 승인 자체는 재고 이동 아님 |
| 실제 품질/가용 상태 | 보류 적용 미확인 / 원천 적용확인 / 원천 해제확인 등 | 확인된 원천 사건·범위·유효시각으로만 표시, 이 화면에 강제 해제 버튼 없음 |

검사 확정과 부적합의 보류 해제는 별도 판단이다. 재검·재작업·폐기 처분이 승인돼도 작업 수행/이동/폐기 증빙이 미확인이라면 수량을 가용·폐기로 미리 바꾸지 않는다. 해제처럼 물리 작업 없는 처분도 authoritative 품질 상태의 적용 확인이 필요하다. 실제 확정 상태명과 원천별 적용 규칙은 구현 전 미결정이다.

## 7 버튼·이벤트 계약

전체 ID는 `S06-E번호`다. 실제 API 경로·DTO·HTTP 상태 코드·저장소는 아직 매핑하지 않았다. 다음 표는 향후 UI/서버가 맞출 동작 제안이다.

### 공통 처리·실패·중복 원칙

1. 대상 ID·현재 revision·단위·범위·입력을 고정하고 필수/타입/상태를 검사한다. 서버는 현재 tenant/site/LOT/artifact/action·위임·원천 소유권을 재검사한다.
2. 쓰기는 기대 버전이 맞을 때 한 번 처리하고 서버 확인 뒤에만 저장/제출/승인을 표시한다. 읽기 응답은 오래된 요청이 새 범위 결과를 덮지 못하게 한다.
3. 같은 사용자 의도의 멱등 참조+같은 입력은 같은 결과, 다른 입력은 충돌이다. 응답 유실은 확정 실패가 아니며 E24로 확인한다. 확인 불가면 입력·참조를 보존하고 새 키로 자동 재생성하지 않는다.
4. 필드 오류는 입력 위치·단위·첫 오류 포커스, 업무 차단은 사유·다음 행동, 권한 거부는 존재를 누출하지 않는 안내, stale 충돌은 내 입력/최신본 비교를 제공한다. 자동 덮어쓰기하지 않는다.
5. 감사는 actor·scope·action·대상/rev·전후 참조·사유·operation·시각·결과의 최소 정보를 남긴다. 원문 증빙·불필요 개인정보·전체 민감 payload를 로그로 복제하지 않는다. 업무 저장/승인과 감사 일관성은 구현 수용조건이다.

## 8 빈·로딩·실패·접근성과 복구

| 상태 | 표시·허용 행동 | 오해/실수 방지 |
|---|---|---|
| 첫 로딩/조회 중 | 범위·표 헤더 유지, 패널별 로딩·쓰기 잠금 | 미확정0건/가용0·확정 성공으로 표시하지 않음 |

키보드로 필터→행 링크→상세 탭→입력→제출/취소에 접근한다. 표본/모수·수량 단위·필수 조건을 텍스트로 읽히게 하고 색만으로 보류/적합/오류를 표현하지 않는다. 패널을 열 때 제목/첫 필드로, 닫을 때 호출 버튼으로 포커스를 돌린다. 로딩·검증 오류·결과 불명을 보조기술에 알리는 방식을 후속 UI에서 검증한다. 좁은 화면은 LOT·검사 상태·보류 적용 확인·수량·기준시각을 먼저 보여주며 복잡한 처분 승인은 데스크톱 우선이다. 모바일 동등 지원은 미설계·미검증이다.
