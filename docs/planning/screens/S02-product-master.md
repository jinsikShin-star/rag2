## 1 시나리오와 이번 묶음의 경계

생산 계획 담당자가 가상 품목 `P100 브래킷`의 승인 개정과 다음 개정을 비교한다. 순중량이 0.8 kg/ea에서 달라진다면 어떤 근거와 유효일을 바꿨는지 확인하고 검토를 요청한다. 품질 담당자는 허용된 개정·근거만 검토한다. 새 개정이 승인돼도 이미 배포한 작업지시의 품목·BOM·라우팅·단위 변환 참조를 자동 교체하지 않는다.

실행 순서는 **사업장·원천 모드 확인 → 품목/개정 검색 → 상세·근거 확인 → 필요 시 새 초안/개정 작성 → 검토 → 권한 있는 승인 → 향후 적용 영향 확인**이다. 승인은 생산 기준정보에 대한 승인으로, 탄소 결과 승인·고객 발행·외부 검증을 뜻하지 않는다.

- **이번 상세화:** 품목의 검색·개정 조회·초안·검토/승인 제안, 중량/단위 근거, 개정 비교와 영향 조회, 제한된 목록 내보내기.
- **후속:** BOM 구성행·라우팅 공정·검사기준·재료·설비 마스터의 실제 편집 화면. 여기서는 연결된 버전과 읽기 참조만 보인다.
- **제안:** 기존 BOM/라우팅의 `작성 중 → 검토 중 → 승인됨 → 사용 중 → 대체됨` 의미를 품목 개정에도 적용한다. 품목별 승인 역할·유효일 전환 정책은 고객 검토 후 확정한다.
- **원천 경계:** 경량 모드라도 고객 지정 기준 시스템을 우선한다. 외부 MES/ERP가 소유한 필드는 직접 수정하지 않고 원천 보완/정정 요청으로 연결한다. 연계 모드를 자체 기준정보 승인으로 바꾸지 않는다.

## 2 역할·진입과 화면이 하는 일

| 역할/범위 | 읽기 | 제안하는 쓰기·검토 범위 | 제한 |
|---|---|---|---|
| 생산 계획 담당자 | 허용 품목·개정·적용 지시 | 자체 소유 필드의 초안·새 개정·검토 요청 | 승인본 덮어쓰기, 외부 원천 필드 직접 수정 불가 |
| 품질 담당자 | 허용 사양·중량 근거·검사기준 참조 | 지정된 검토·반려 의견 | 생산/탄소 모든 승인 권한을 자동 부여하지 않음 |
| 지정 기준정보 승인자 | 배정된 품목과 검토 diff | 사업장 정책이 위임한 개정 승인 | 고객 겸직·예외 정책 확인 필요 |
| ESG 분석가·제한 열람자 | 승인된 허용 품목/단위 근거 | 이 화면에서는 읽기 | 원본 수정·전체 BOM/원가·다른 제품 export 불가 |

권한은 `tenant ∩ site ∩ 허용 품목 ∩ action`으로 서버에서 매번 재검사한다. 다음 이벤트의 쓰기/검토/승인/export 권한은 **설계상 action 구분**이며 실제 권한 코드·역할 매핑은 미구현이다. 작성자와 승인자가 같은 내부 검토는 기존 기획의 경고·기록 가능한 예외 제안을 따른다. 고객 공식 발행은 별도 승인 분리 정책이며 이 화면에서 허용하지 않는다.

진입은 기준정보 메뉴, 작업지시의 품목 링크, LOT 상세의 품목 링크다. 직접 링크도 같은 범위를 검사하고 권한 없는 품목의 존재·명칭을 알려주지 않는다. 뒤로 가면 마지막 **확정 조회 조건·페이지·선택**을 복원하되 새 권한과 최신 상태를 재검사한다.

## 3 S02-L 품목 목록 와이어프레임

```text
+-------------------------------------------------------------------------------------+
| 조직: DEMO / 사업장: SITE-A [범위 변경 PL10] | 경량 모드 | 마지막 조회: 15:00 (가상)     |
| 기준정보 > 품목 목록                     | 조회 범위: 허용 품목 | 원천 지연: 없음        |
+-------------------------------------------------------------------------------------+
| 품목코드/명 [____________] 유형 [제품 v] 상태 [전체 v] 유효일 [2026-11-03]               |
| 이전 개정 포함 [x]  원천 [전체 v]              [조회 PL01] [초기화 PL02]                 |
| [신규 초안 PL06] [선택 개정 비교 PL07] [선택 목록 내보내기 PL08] 선택 0개 (현재 페이지)  |
+-------------------------------------------------------------------------------------+
| [ ] PL04 | 품목코드 ↑ PL03 | 개정 | 표시명   | 기준단위 | 순중량/근거 | 상태 | 원천        |
| [ ]      | P100 [열기 PL05]| r3   | 브래킷   | ea       | 0.8 kg/ea  | 승인 | 자체 작성   |
| [ ]      | P100 [열기 PL05]| r4   | 브래킷   | ea       | 미입력     | 작성 | 자체 작성   |
| [ ]      | P200 [열기 PL05]| r2   | 커버     | ea       | 근거 제한  | 사용 | ERP 참조    |
+-------------------------------------------------------------------------------------+
| 조회 3행 / 선택 0개 | [이전 PL03] 1 / 1 [다음 PL03] | 페이지 크기 [25 v] PL03            |
| 내보내기 작업: 없음 / 처리 중 / 결과 확인 필요 [작업 상태 PL09] [결과 다운로드 PL11]     |
+-------------------------------------------------------------------------------------+
```

한 행은 `품목 ID + 개정 ID`다. 이전 개정 포함을 끄면 유효일 기준 대표 개정만 표시한다. 예시에서는 개정 비교를 위해 이전 개정을 포함했다. 제품과 재료 유형을 혼합 집계하지 않으며 서로 다른 기준단위의 무의미한 합계를 표시하지 않는다.

검색 영역은 조회 대상을 좁히고, 개정·원천·근거 열은 쓰기 가능 여부와 수치 해석을 돕는다. 선택은 현재 페이지의 명시적 ID 집합이며 다른 페이지·필터로 넘어가면 해제한다. **전체 검색 결과를 몰래 선택하지 않는다.** 서버 정렬 기준과 동률 해소키를 고정할 것을 제안하며 페이지 크기·최대 export 행수는 미결정이다.

## 4 S02-D 품목 상세 와이어프레임

```text
+-------------------------------------------------------------------------------------+
| DEMO / SITE-A / 경량 모드 | 기준정보 > P100 > r3 | [목록으로 PD01]                       |
| P100 브래킷 / r3 / 승인됨 | 원천: 자체 작성 | 유효: 2026-11-01~ | 최신 확인: 15:00       |
| [편집 PD02: 승인본 불가] [새 개정 PD07] [검토 요청 PD04] [승인 PD05] [반려 PD06]          |
| 배너: 승인본은 읽기 전용. 품목 승인과 탄소 결과/고객 발행 승인은 다릅니다.                |
+-------------------------------------------------------------------------------------+
| [기본정보] [개정 비교] [단위·근거] [연결 버전] [향후 지시 영향] [감사]  탭 전환 PD09       |
| 기본정보: 코드 P100 / 이름 브래킷 / 유형 제품 / 기준단위 ea / 유효 시작·종료               |
| 변경 이유: __________________  | 순중량: 0.8 [kg/ea] | 순/총·건/습 기준: 순·건             |
| 단위 근거: E-DEMO-01 / 개정1 / 적용일 / 접근 상태 [근거 열기 PD10] [근거 첨부 PD11]       |
| 연결: BOM r5 · 라우팅 r2 · 검사기준 r1 (읽기 참조 PD10, 편집 화면은 후속)                |
| 비교 기준 [r2 v] -> r3 [비교 PD08] | 영향 기준일 [2026-11-03] [영향 조회 PD12]            |
| 검토 의견/반려 사유 [________________________] [원천 보완·정정 요청 PD13]                |
+-------------------------------------------------------------------------------------+
| 초안 편집 영역(편집 가능할 때만): 수정됨 / 서버 저장됨 / 저장 결과 확인 필요               |
| [저장 PD03] [변경 취소 PD14] | 처리 참조 OP-DEMO (가상) [처리 상태 확인 PD15]              |
| 감사: [이 개정 이력 PD16] | 승인자·시각·변경 이유 / 이전 개정 연결 / 영향 조회 범위          |
+-------------------------------------------------------------------------------------+
```

요약은 무엇을 보고 있는지와 유효 상태를, 단위·근거 탭은 환산을 사용할 수 있는 이유를 보여준다. 향후 지시 영향은 **조회 시점의 후보**이며 배포된 지시를 변경하지 않는다. 비교는 같은 품목의 명시한 두 개정만 대상으로 하고 근거 열람 권한이 없으면 내용 대신 제한 상태를 보인다. 감사 탭에서 일반 사용자는 기록을 수정·삭제하지 못한다.

탭·패널은 설명을 위한 제안이다. BOM/라우팅 등의 링크가 아직 상세 설계되지 않았다면 `후속 설계`를 표시하고 실제로 이동 가능한 UI처럼 보이지 않게 한다. 승인본에서 저장·검토 요청·반려 등을 숨기거나 비활성 사유를 보이는 최종 방식은 접근성 검토에서 확정한다.

## 5 필드 계약 — 필수·단위·원천·편집 경계

| 필드 | 필수 시점 | 단위/형식 | 원천·검증 | 편집 가능 범위 |
|---|---|---|---|---|
| tenant/site·불변 품목 ID·개정 ID | 모든 조회/쓰기 | 식별자 | 서버의 허용 범위, 표시용 코드와 분리 | 서버 지정, 임의 변경 불가 |
| 품목코드·외부키 | 초안 최초 저장 | 문자열 | 고객 키·원천+site의 품목 ID 고유성 검사; 같은 품목의 새 개정은 같은 코드 유지, 대소문자 자동 치환 없음 | 신규 자체 초안만, 이후 변경 절차 미결정 |
| 표시명·유형 | 초안 저장 | 문자열 / 제품·반제품 등 코드 | 고객 허용 분류, 공백만 입력 차단 | 자체 작성 중; 외부 필드는 읽기 전용 |
| 기준단위 | 초안 저장 | ea, kg 등 허용 단위 코드 | 원천 및 단위표와 일치, 임의 새 단위 생성 불가 | 사용 실적이 있으면 새 개정·영향 검토 |
| 유효 시작/종료 | 검토 요청 | 사업장 현지 날짜, 종료 의미는 고객 정책 | 시작≤종료, 동일 용도의 승인 유효기간 중첩 검사 | 자체 작성 중; 승인 뒤 새 개정 |
| 순중량·수량 기준 | 환산을 사용할 때 | kg/ea 등 분자/분모 단위 | 양수·차원·순/총·건/습 기준·근거와 일치 | 자체 작성 중, 근거 없이 ea↔kg 환산 금지 |
| 측정/변환 근거·개정·적용일 | 환산 검토 요청 | Evidence ID·변환 개정 | 문서 접근·유효일·품목/개정 적용 범위 검증 | 승인 전 제안, 승인본 근거 교체 불가 |
| BOM/라우팅/검사기준 참조 | 향후 작업 배포에 필요 | 불변 개정 ID | 현재 승인·유효성, 참조 열람 범위 | 이번 묶음은 읽기, 편집은 후속 |
| 변경 이유·검토/반려 의견 | 새 개정/검토/반려 | 텍스트 | 필수 사유 누락 차단, 민감정보 입력 경고 | 해당 action 권한자 |
| 원천·원천개정·마지막 동기화 | 외부 연계 자료 | 안전한 참조·시각 | 같은 원천키/개정의 다른 내용은 충돌 | 원천에서 관리, 로컬 직접 수정 금지 |
| 화면 편집 버전·operation 참조 | 변경 요청/결과 조회 | 불투명 식별자 | 현재 버전 비교·멱등 판정, 비밀값 아님 | 서버 발급·관리 방식 후속 결정 |

순중량을 모르면 `미확인`으로 보이며 0으로 채우지 않는다. ea 기준 품목 조회 자체는 가능하되, 질량 환산이 필요한 검토/적용은 근거 부족으로 막는다. 0.8 kg/ea 예시는 실제 계량·도면·고객 승인 증거가 아니다. 표시 반올림과 저장 정밀도·허용 오차는 별도 검토하며 여기서 임의 고정하지 않는다.

## 6 공통 이벤트 처리 계약

다음은 **향후 구현할 동작의 제안**이다. 실제 API 경로·DTO·DB·멱등 저장소·인증은 정하지 않았다. 모든 이벤트는 서버가 현재 권한·소유 원천·대상 상태·기대 버전을 재검사한다. UI 비활성화만으로 권한을 보장하지 않는다.

- 읽기는 같은 조건/개정 조회의 반복이 데이터를 바꾸지 않는다. 더 늦게 도착한 이전 조회 응답이 새 범위·필터의 결과를 덮지 않게 한다.
- 쓰기는 사용자 의도 하나에 operation/멱등 참조를 묶는다. 같은 참조+같은 입력은 같은 결과를 반환하고 다른 입력이면 충돌한다. 새로 고침·다중 클릭마다 새 의도를 만들지 않는다. 보관 기간·조회 계약은 미결정이다.
- 타임아웃·연결 단절은 `실패 확정`이 아니라 `결과 확인 필요`다. 입력을 유지하고 PD15/PL09로 처리 상태를 확인한다. 서버 결과 확인 전에는 `저장됨/승인됨/내보내기 완료`라고 표시하지 않는다. 권한이 회수됐다면 결과도 열람시키지 않는다.
- 버전 충돌은 최신 값과 자신의 변경을 따로 제시한다. 승인본이나 다른 작성자의 변경을 자동 병합/덮어쓰기하지 않고 재조회·비교 후 새 의도를 만든다.
- 감사는 actor·tenant/site·대상/개정·action·시각·처리 참조·결과·변경 이유·허용된 변경 전후 참조를 남긴다. 원문 첨부나 전체 민감 payload를 로그에 복사하지 않는다. 모든 저장/승인과 해당 감사 기록의 일관성은 구현 수용조건이다.

## 7 빈·로딩·실패와 접근성 상태

| 상태 | 화면 표시·사용자가 할 수 있는 행동 | 방지할 오해 |
|---|---|---|
| 최초 빈 목록 | 허용 범위/필터와 `조회 결과 없음`; 작성 권한이 있으면 PL06 | 다른 범위 품목 수·명칭을 보여주지 않음 |
| 최초 로딩 / 페이지 로딩 | 영역별 로딩 텍스트, 표 헤더 유지, 확정 전 선택/쓰기 잠금 | 0건 확정이나 저장 성공으로 표시하지 않음 |
| 필드 오류 | 필드 옆 이유·필수/단위 텍스트, 상단 오류 요약에서 첫 오류 이동 | 색만 바꾸거나 입력 전체를 지우지 않음 |
| 권한 없음/만료 | 공통 제한 메시지·재인증/담당자 경로; 미저장 입력의 안전한 처리 안내 | 품목 존재·제한 근거·다른 tenant 정보를 누설하지 않음 |
| 지연·오래된 데이터 | 마지막 성공 조회·원천 동기화 시각과 재조회 | 이전 성공 표를 최신 확정본처럼 보이지 않음 |
| 일부 탭/영향 조회 실패 | 성공 영역 유지, 실패 범위·재시도만 표시; 관련 승인 판단 보류 | 일부 결과를 전체 영향 0건으로 표현하지 않음 |
| 충돌·동일 요청 반복 | 자신의 입력/최신 버전 diff, 처리 참조·PD15 경로 | 승인본 자동 덮어쓰기·이중 생성 금지 |
| 첨부 격리/사용권 미확인 | 검사/권리 대기 배지, 근거 부족 이유 | 업로드 수신을 사용 가능 근거로 오인하지 않음 |

키보드로 필터→조회→행 링크→페이지→상세 탭→주요 action 순서로 이동한다. 표 머리글·정렬 방향·선택 건수를 텍스트로 읽을 수 있게 하고, 모달 종료 시 여는 버튼으로 포커스를 돌린다. 단위는 placeholder에만 두지 않고 필드/열 제목에도 유지한다. 새 오류/저장 결과는 포커스를 빼앗지 않는 상태 알림과 연결한다. 좁은 화면은 품목·개정·상태·단위를 우선 보이고 나머지는 행 상세로 펼친다. 복잡한 개정 비교와 승인은 데스크톱 우선 설계이며 모바일 동등 지원은 미검증이다.

| PA08 | 승인 권한이 회수되거나 검토본이 바뀜 → PD05 → 서버가 차단하고 초안·승인 기록을 임의 생성하지 않는다. |
| PA09 | 품목 읽기는 가능하지만 근거/export는 불가 → PD10/PL08 → 해당 내용과 다운로드를 차단하고 기본 상세만 유지한다. |
| PA10 | 필터를 바꾸고 이전 조회 응답이 늦게 도착 → 새 조회 완료 → 새 범위의 결과를 유지하고 이전 선택은 해제한다. |
| PA11 | 외부 정정 요청 후 동일 원천 정정 수신 → 대응 확인 → 요청/원천 연결을 검토하고 같은 변경을 두 번 적용하지 않는다. |
| PA12 | 품목 승인 또는 내부 목록 반출 성공 → 탄소 보고 화면 참조 → 탄소 승인·공식 발행·외부 인증 상태로 자동 승격하지 않는다. |

## 9 검토할 가정·미결정과 다음 작은 작업

- **A-P01 제안:** 품목도 BOM/라우팅과 같은 개정 상태 의미를 사용한다. 품목 승인자·검토자의 고객별 배정과 내부 겸직 예외를 확인한다.
