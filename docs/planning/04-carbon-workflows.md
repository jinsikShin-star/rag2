# 탄소 사용자 여정과 화면 및 보고 기획

[문서 안내](README.md) · [제품 방향](00-product-direction.md) · [MES 업무](01-mes-workflows.md) · [데이터와 보안](02-data-contract-and-security.md) · [탄소 방법](03-carbon-methodology.md) · [탄소 화면](04-carbon-workflows.md) · [출시와 사업](05-launch-and-commercial.md) · [AI와 결정](06-ai-discovery-and-decisions.md)

> 상태: 기획 검토본 · 기준일: 2026-11-03 · 버전: 1.0
> 이 문서의 기능·운영·가격·성과 기준은 제안이며, 구현 또는 인증 완료를 뜻하지 않는다.

분석가가 값을 계산하는 일뿐 아니라 검토·승인·고객 발행과 후속 정정을 끝내는 흐름을 설계한다.

## 1 핵심 사용자 여정


1. 사업장·제품군·원천 시스템과 담당자를 등록한다.
2. 산정 목적과 수신자를 정하고 경계·기준단위·기간·방법 버전을 잠근다.
3. MES/ERP/CSV에서 원본을 가져와 매핑·중복·단위·수지를 점검한다.
4. 차이를 해결하고, 필요한 경우 근거와 함께 추정·제외·배분 정책을 승인받는다.
5. 계수 후보를 비교하고 적용 계수·공급사 PCF를 승인한다.
6. 고정된 스냅샷으로 실행한다. 오류와 경고를 나눠 처리한다.
7. 공정별 결과·데이터 품질·민감도·제외 목록을 검토한다.
8. 작성자와 별도 승인자가 결과를 승인한다.
9. 승인된 공개 항목을 선택하고 고객별 패키지를 발행한다.
10. 늦은 실적·공급사 수정·계수 변경이 생기면 기존 결과를 덮어쓰지 않고 영향 분석 후 새 버전을 발행한다.

첫 사용자가 해야 할 다음 행동은 항상 화면 상단에 하나로 제시한다. 예를 들어 '100 kWh 미배분 해결', '공급사 PCF 기준단위 확인', '검토 요청'이다. 단순한 완료율 막대만으로 잘못된 데이터를 완료 처리하지 않는다.

## 2 핵심 화면과 액션


| 화면 | 주요 정보 | 사용자 액션 | 필수 실패 처리 |
|---|---|---|---|
| 업무 홈 | 마감 임박 연구, 차단 오류, 검토 대기, 공급사 요청 | 담당 배정, 다음 행동 이동 | 분모 없는 추정치를 정상 KPI와 구별 |
| 사업장 데이터 연결 | 원천별 소유권, 최근 동기화, event lag, 실패행 | CSV 검증, mapping 승인, 재시도 | 미확정 중복·부분 실패를 눈에 띄게 표시 |
| 제품과 경계 | 제품 revision, 기능·기준단위, 포함 공정, 제외 목록 | 새 연구, 범위 복제, 경계 승인 | 다른 범위 복제 시 승인 초기화 |
| 실적 근거원장 | 실제 소비, 양품, WIP, scrap, rework, source link | 근거 조회, 정정 요청 | 원천 authoritative 데이터 직접 수정 금지 |
| 에너지 배분 | meter hierarchy, interval, 배분합, driver, 미배분 | 배분 시뮬레이션, 정책 승인 | 중복 구간·분모 0·미배분 차단 |
| 공급사 자료함 | 품목별 요청·수신·경계·기간·권한 | 요청안, 문서등록, 검토, 보완 요청 | 수신=사용가능으로 처리 금지 |
| 계수 선택 | 적합성, 지역·연도·범위·라이선스, 대안 차이 | 비교, 승인 적용, 새 revision | 단위·GWP·경계 충돌 차단 |
| 데이터 품질 | source별 품질, 결측, 예외 만료, 영향 후보 | 담당 배정, proxy 요청 | 근거 없는 0 또는 자동 완료 금지 |
| 산정 실행 | input snapshot, method, warnings, 실행 상태 | 검사, 실행, 취소, 재실행 | 중복 클릭은 동일 job로 처리 |
| 결과 분석 | total, per-unit, 단계별 기여, 품질, 제한 | 원본 drilldown, 같은 범위 비교 | 미검토 초안은 초안 배지를 명시하고 고객 공식 발행 차단 |
| 시나리오 | 실제 baseline, 변경 가정, 비용·제약, 탄소차이 | 공급사·소재·배분 가정 비교 | 실제 실적을 덮어쓰지 않음 |
| 승인함 | 변경 diff, 오류/예외, 근거, 승인 이유 | 승인, 반려, 수정 요청 | self-approval 정책과 역할 검사 |
| 보고·교환 | 수신자별 공개 필드, 방법, 버전, 공유 이력 | 미리보기, 내보내기, 발행 승인 | draft/rights 미충족/범위미달 차단 |
| 감사·관리 | 권한, 접근로그, 보존·데이터 삭제, connector 권한 | 권한검토, 제한된 export | cross-tenant 조회와 관리자 남용 차단 |

모든 화면에 빈 상태, 권한 없음, 데이터 지연, 오류, 오래된 데이터, partial load, 충돌과 동기화 재시도 상태를 설계한다. 모바일은 작업·계량·근거 확인에 맞추고, 복잡한 경계·계수·배분 검토는 데스크톱 우선으로 한다.

## 3 보고서와 고객 데이터 교환


### 기본 보고서 패키지

보고서 첫 페이지는 결과보다 범위를 먼저 오해 없이 전달해야 한다. 제품과 revision, 회사·사업장, 대상기간, 기준단위, 경계, 목적, 방법 버전, 결과, 승인 상태, 주요 제외·한계가 필수다. 본문에는 흐름도, 데이터 출처, 계수·할당·재활용 정책, 품질, 불확실성·민감도, 변경 이력, 리뷰 기록을 넣는다. 고객별 공개본과 내부 근거본을 분리한다.

계산 workbook/CSV는 숫자만 아니라 단위와 각 행의 근거 ID를 포함한다. 승인된 PDF/문서, machine-readable result, 필요한 증빙 목록, manifest를 묶을 수 있다. 상용 LCI 원자료·공급사 기밀은 무조건 첨부하지 않으며 사용권한이 허용하는 메타데이터와 계산근거를 제공한다. 'ISO certified report' 같은 자동 제목을 제공하지 않는다.

### 외부 교환

PACT는 PCF 데이터 모델과 교환 API를 제공하고 계산 방법 문서와 기술 규격은 구분된다. 공식 목록은 확인 시점에 3.0.3을 latest stable로 표시했다. 따라서 구현 단계에서 대상 버전·필수 필드·변경 및 철회 처리·인증·접근권한·적합 시험을 다시 확인해야 한다. CSV/JSON으로 비슷한 필드를 내보낸다고 PACT 적합 솔루션이라고 할 수 없다. [PACT 공식 기술 규격 목록](https://docs.carbon-transparency.org/data-exchange-protocol/)

교환단위는 '고객에게 허가된 승인 결과'다. 공개 PCF와 근거 전체를 동일 권한으로 보지 않는다. 수신자는 누구인지, 어느 제품·기간을 요청했는지, 어떤 필드를 받을 수 있는지 확인한다. 저장 후 다운로드 재시도는 같은 발행 ID를 유지하고, 동일 결과의 중복 통지는 막는다. 상대 시스템 실패는 내부 결과 승인을 롤백하지 않고 delivery 상태를 별도 관리한다.

EPD 지원은 나중 모듈이다. 적용 PCR, 프로그램 규칙, 검증자·검토·등록 절차가 필요하므로 산정 PDF를 생성했다고 EPD가 발급된 것으로 표시하지 않는다. EPD International 공개 안내는 PCR 선택, LCA, 검증·등록 등 절차를 구분한다. [EPD 개발 절차](https://ps.prod.environdec.com/getting-started/epd-development), [공식 자료실](https://www.environdec.com/resources/resource-library)


## 4 화면 및 보고서 수용 기준

- [ ] 14개 화면 모두 빈 상태·권한 없음·지연·충돌·부분 실패·재시도 상태가 있다.
- [ ] 보고서 첫 페이지에서 제품·기간·단위·경계·제외·상태·버전이 보인다.
- [ ] 결과에서 원천 사건·근거·계수·배분 개정으로 내려갈 수 있다.
- [ ] 초안·내부 승인·외부 검증·고객 발행 상태를 혼동하는 배지나 문구가 없다.
- [ ] 공유 대상·필드·라이선스·수신자 권한을 확인하며 과거 발행본을 조용히 바꾸지 않는다.
