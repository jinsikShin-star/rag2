## 1 표준 참고와 시스템 책임 경계


ISA의 공개 설명은 ISA-95를 제조 운영과 기업 업무 사이의 정보 교환 모델로 소개하고 Level 3 제조 운영과 Level 4 업무 시스템 간 경계를 설명한다. 본 기획은 이를 업무 경계와 용어 정리에 참고한다. 유료 표준 전문을 검토한 인증 설계가 아니다. [ISA 공식 ISA-95 소개](https://www.isa.org/standards-and-publications/isa-standards/isa-95-standard)

OPC Foundation의 공개 Machinery Job Management 모델은 작업 요청과 실행 결과를 구분하고, 작업의 시작·일시정지·중단 및 결과 제공을 별도 개념으로 설명한다. 본 기획도 작업지시와 실제 결과를 분리한다. OPC UA 연결 또는 규격 적합 구현은 v1 약속이 아니다. [OPC Foundation Machinery Job Management](https://reference.opcfoundation.org/specs/OPC-40001-3/6), [OPC Foundation ISA-95 Job Order 개요](https://reference.opcfoundation.org/specs/OPC-10031-4/4)

| 영역 | 원천 책임 | 본 제품 v1 역할 | 경계 |
|---|---|---|---|
| 고객·수주·납기·원가회계 | ERP 또는 고객 업무시스템 | 필요한 주문번호·목표 수량을 참조 | 매출·세금·회계전표 생성 제외 |
| 품목·BOM·라우팅 | 고객 지정 기준 시스템 | 승인본 버전 보관과 작업지시 스냅샷 | PLM 전체 대체 제외 |
| 작업지시·공정 실적 | 경량 모드 본 제품, 연계 모드 기존 MES | 승인된 원천 우선순위에 따라 기록 | 동일 작업 이중 확정 금지 |
| 설비 운전과 안전 | PLC·SCADA·현장 안전체계 | 데이터 읽기 및 수기 상태 기록 | 설비 기동·정지·설정값 변경 금지 |
| 품질 | 본 제품의 기초 검사·처분 또는 기존 QMS | 검사결과·보류·처분·계보 관리 | 고도 SPC·CAPA·규제 전자서명 제외 |
| 원재료·완제품 재고 | ERP/WMS 또는 단순 로트 원장 | 투입·반납·산출·WIP 이동 수량 기록 | 재무재고와 일치한다고 자동 주장하지 않음 |
| 전기·연료·용수 | 계량기·청구서·설비 수집 | 원자료 검증 및 범위·배분 근거 | 청구서 총량과 중복 더하지 않음 |
| PCF·LCA | ESG 계산·승인 도메인 | 생산 근거 제공, 영향 분석 | MES 승인만으로 외부 공표 불가 |

### 원천 우선순위

사업장과 데이터 종류별로 authoritative source를 하나 정한다. 예: 작업지시 ERP, 실적 기존 MES, 전기 총량 전력계, 품질 본 제품. 같은 키의 데이터가 다른 경로에서 들어오면 최신 입력값을 무조건 채택하지 않고 충돌함으로 보낸다.

수동 보완은 빈 필드에 대한 보완인지 원천 실적의 정정인지 구분한다. 기존 MES 실적 오류는 원본을 고치지 않고 정정요청 또는 승인된 보정 이벤트를 연결한다. 원천 시스템이 후에 같은 정정을 보내면 대응 관계를 확인해 중복 조정하지 않는다. 어느 시스템의 숫자가 공식인지 고객과 도입 시 서명 가능한 책임표로 합의한다.


## 2 사용자 역할과 권한


| 역할 | 주요 일 | 가능한 행동 | 제한 |
|---|---|---|---|
| 고객 조직 관리자 | 사업장·사용자·권한 관리 | 초대, 역할 지정, 기준 정책 관리 | 생산 사실·계수·산정 결과를 단독 승인하지 않음 |
| 생산 계획 담당자 | 작업지시와 공정 배포 | 초안 생성, BOM/라우팅 선택, 배포 요청 | 실행된 지시의 버전을 덮어쓰지 않음 |
| 현장 작업자 | 투입·작업·결과 기록 | 배정된 작업 시작/중지, 수량·불량·자재 등록 | 보류 해제, 마감, 과거 확정값 직접 변경 불가 |
| 반장·생산 관리자 | 실행 관리와 운영 승인 | 배포 승인, 예외 승인, 공정·지시 마감 | ESG 방법론 승인 및 외부 공유 별도 권한 |
| 품질 검사자 | 검사와 부적합 기록 | 검사결과 등록, 보류 제안 또는 즉시 보류 | 자신의 부적합 처분을 단독 승인하지 않음 |
| 품질 승인자 | 해제·재작업·폐기 판단 | 품질 보류 해제, 조건부 승인, 처분 승인 | 설비 운전 명령 불가 |
| 에너지 담당자 | 계량기와 배분 | 수집값 검토, 배분안 작성, 누락 사유 | 자신이 작성한 중요 배분 변경 단독 승인 불가 |
| ESG 분석가 | 산정 입력·방법론 관리 | 생산 스냅샷 선택, 계수 매핑, 시나리오 | 생산 원본 직접 수정 금지 |
| ESG 승인자 | 결과 검토와 공개 판단 | 결과 승인·반려, 공개본 선택 | 운영 마감을 대신하지 않음 |
| 고객사·검증인 열람자 | 승인된 자료 검토 | 허용된 제품·기간의 문서와 증빙 읽기 | 타 제품 BOM, 전체 공장 원가, 다른 고객 정보 접근 불가 |
| 공급사 기여자 | 지정 요청 자료 제출 | 자기 조직의 지정 요청만 입력 | 본 공장 생산 데이터 접근 불가; v1 이후 |
| 서비스 운영자 | 장애와 지원 | 승인된 한시 지원 접근 | 기본적으로 고객 실적 열람 불가, 접근 사유·기간·로그 필수 |

권한은 tenant, site, 역할, 허용 제품/프로젝트 범위의 교집합으로 판정한다. UI 숨김만으로 권한을 구현하지 않는다. API, 검색, 다운로드, 증빙 미리보기, 감사로그에도 같은 범위를 적용한다. 소규모 고객의 겸직은 가능하지만 작성자와 최종 승인자가 같을 때는 경고와 예외정책을 남긴다. 마감 후 정정은 2인 검토를 권고하고, 고객용 공식 발행은 작성자와 최종 승인자 분리를 출시 정책으로 제안한다.


## 3 상태와 승인 모델


### 기준정보와 작업지시

BOM/라우팅 버전: 작성 중 → 검토 중 → 승인됨 → 사용 중 → 대체됨. 승인 버전은 수정하지 않고 새 버전을 만든다. 유효일, 변경 이유, 승인자, 대체 관계를 가진다. 작업지시는 배포 시점의 BOM·라우팅·단위 변환·검사기준 버전을 참조한다. 새 BOM이 승인돼도 실행 중인 지시는 바뀌지 않는다.

작업지시 실행 상태: 초안 → 배포됨 → 실행 중 → 작업 완료 → 운영 마감. 일시정지는 실행 중 상태의 별도 실행 플래그로, 품질 보류는 별도 품질 축으로 관리한다. '보류' 한 단어로 생산중지·검사대기·재료부족을 섞지 않는다.

- 배포 조건: 승인된 품목·BOM·라우팅, 유효 단위, 작업장, 목표 수량, 책임자. 자재 부족은 경고 또는 차단으로 사업장 설정하되 정책을 버전 관리한다.
- 시작 조건: 배포된 공정, 필요한 선행공정 완료, 해당 수량에 활성 품질 보류 없음, 필수 자재 식별 완료.
- 작업 완료 조건: 작업시간·투입·산출·미처리 수량 정리. 작업자 완료는 품질 승인이나 운영 마감을 의미하지 않는다.
- 운영 마감 조건: 미결 품질 처분 없음, 로트 수량 정합, 필수 승인·증빙 완료, 허용된 범위의 에너지 입력 검증. ESG 산정을 위한 기간별 에너지 배분은 별도 게이트가 있을 수 있다.
- 취소: 미실행 지시는 취소 가능. 이미 투입한 지시는 삭제하지 않고 중단 사유와 잔여 자재·WIP 처분을 기록한다.
- 마감 후 변경: 지시를 과거 상태로 되돌려 원본을 덮지 않는다. 정정요청 → 검토 → 승인/반려 → 새 운영 스냅샷 생성으로 처리한다.

### 공정 실행 상태

대기 → 준비 → 작업 중 ↔ 일시정지 → 결과 제출 → 확인 완료. 중단과 취소는 별도 종료 사유다. 준비시간·가동시간·비가동시간을 구분한다. 지시가 하나여도 설비별 실행 세션은 여러 개일 수 있다. 여러 작업이 같은 설비에서 겹치면 허용된 병렬설비인지 확인하고, 비병렬설비는 충돌로 표시한다.

### 로트의 수량과 품질

로트 상태를 단일 문자열 하나로 표현하지 않는다. 위치, 가용수량, 품질 처분, 흐름 상태가 다르다.

- 흐름: 생성 → 재공 → 완성 → 소비/출하됨 또는 폐기됨.
- 품질: 검사대기, 적합, 보류, 재작업 필요, 부적합 처분 완료.
- 수량 버킷: 투입 대기, 공정 중, 검사 대기, 양품, 재작업 대기, 폐기, 반납, 이관. 같은 시점의 같은 실물 단위가 상호 배타적인 버킷에만 존재하도록 한다.
- 부분 보류: 100개 중 10개를 보류하면 해당 수량을 자식 로트 또는 명확한 수량 구간으로 분리한다. 로트 전체와 일부 보류를 모호하게 표현하지 않는다.
- 보류 중에는 소비·출하 준비·다음 공정 확정을 차단한다. 실제 물리 작업이 이미 진행됐다면 사실 기록 자체를 막아 숨기지 않고 규정위반 예외로 기록한 뒤 품질 처분을 요구한다.

### 정정과 데이터 승인

정정요청은 대상 이벤트, 변경 전후 값, 사유, 증빙, 작성자, 영향받는 수량/기간/산정 결과를 갖는다. 작성자는 반려된 요청을 보완할 수 있다. 승인된 정정은 원본 이벤트를 지우지 않고 supersedes 또는 reversal+replacement로 연결한다. 한 제품 안에서는 방식 하나를 정하고 모든 도메인에서 일관되게 사용한다. 제안은 revision+supersedes 방식이며 금액 회계식 음수 전표는 v1에서 일반화하지 않는다.

승인된 데이터 스냅샷은 원천 이벤트 집합과 버전, 시간 범위, 마감자, 마감 시각을 고정한다. 늦게 들어온 데이터는 다음 스냅샷에 반영되고 이전 산정 결과에 '원천 변경 있음' 표시를 만든다. 기존에 공유한 PCF 파일을 조용히 교체하지 않는다.


## 4 화면과 작업 흐름


### S01 조직과 사업장 설정

대상: 조직 관리자. 사업장, 현지 시간대, 업무일 경계, 교대조, 단위, 사용자, 역할, 원천 우선순위를 설정한다. 필수 설정 누락 시 온보딩 체크리스트가 막힌다. 시간대 변경은 미래 적용이며 과거 이벤트의 원래 현지 시각과 UTC는 유지한다. 샘플 데이터와 실데이터 공간을 명확히 구분한다.

### S02 품목과 생산 기준정보

대상: 생산 계획 담당자, 품질 담당자. 품목·재료·설비·작업장·BOM·라우팅·검사기준을 버전별로 본다. BOM에는 계획 투입량과 대체 가능한 재료를, 라우팅에는 순서·작업장·표준시간·검사 지점을 둔다. 품목중량, ea↔kg 변환, 포장 단위는 별도 근거와 유효일을 가진다. 이전/현재 버전 비교와 영향받을 미래 작업지시 목록을 제공한다.

### S03 작업지시 보드

대상: 생산 계획 담당자와 반장. 납기·공정·작업장·우선순위별 지시를 필터링하고 초안 생성, 검토, 배포, 중단을 수행한다. 시작 전 예상 자재 부족·부적합 자재·공정순서 위반·중복 지시번호를 표시한다. v1은 사람의 우선순위 편집이며 납기 최적화나 자동 APS를 주장하지 않는다.

### S04 현장 작업 실행

대상: 작업자. 태블릿/공용 단말에서 작업선택 → 작업자 확인 → 자재·로트 확인 → 시작 → 양품/불량/시간 입력 → 제출의 짧은 흐름을 제공한다. 큰 버튼, 숫자 키패드, 단위 노출, 바코드 스캐너 입력 지원, 마지막 저장 시각을 기본으로 한다. 공용 단말은 작업자 전환을 명시하고 세션을 자동 잠근다. 오프라인 입력은 v1 전체 범위가 아니다. 통신이 끊기면 저장 여부를 분명하게 알리고 임시 메모 및 복구 CSV 절차를 안내한다. 사용자에게 저장 완료라고 보인 값은 서버 확인 후에만 확정 표시한다.

### S05 로트 상세와 계보

대상: 생산·품질·ESG 담당자. 로트의 원료, 투입 작업, 공정, 산출물, 분할·병합, 검사, 보류, 폐기, 스냅샷을 한 화면에서 추적한다. 상류 역추적과 하류 영향 범위를 제공한다. 분할은 부모 잔량과 자식 합계를, 병합은 투입 부모별 수량을 표시한다. 물리적 혼합과 단순 박스/팔레트 묶음을 구분한다. 포장 집합은 자식 정체성을 유지하므로 제조 로트 병합으로 처리하지 않는다.

### S06 검사와 품질 보류

대상: 검사자·품질 승인자. 입고/공정/최종검사를 기록하며 측정 항목, 단위, 규격 버전, 표본 수, 검사결과, 첨부를 저장한다. 검사 샘플의 결과를 전체 수량 검사로 표시하지 않는다. 부적합은 원인 코드와 처분 후보를 만들고, 승인자가 해제·재검·재작업·폐기·조건부 사용을 결정한다. 조건부 사용은 허용 범위와 만료를 기록하고 외부 고객 승인 절차가 있다면 증빙을 요구한다.

### S07 재작업과 폐기

대상: 반장·품질 담당자. 원 공정과 로트에 연결된 재작업 작업을 만들고 추가 재료, 시간, 에너지를 별도 기록한다. 회복된 양품은 기존 부적합 수량을 상태 전환한 것으로 처리하며 신규 생산량으로 다시 더하지 않는다. 폐기는 수량·질량·폐기물 종류·발생 공정·처분 일자·인계 증빙을 기록한다. 판매된 스크랩과 공제품은 운영상 구분하되 탄소 크레딧을 자동 부여하지 않는다. 스크랩은 경제가치, 재활용 경로, 적용 방법론에 따라 폐기물 또는 공제품 등으로 다르게 다뤄질 수 있으므로 MES 품목분류만으로 LCA 처리방식을 확정하지 않는다.

### S08 설비 상태와 비가동

대상: 작업자·반장. 설비별 계획 시간, 가동, 준비, 고장, 자재 대기, 품질 대기, 계획 정지를 기록한다. 겹치는 비가동 구간·종료 전 시작·자정을 넘는 구간을 검증한다. 비가동 사유를 모르면 '미분류'로 남기고 마감 전 정리한다. OEE는 표준 사이클·계획생산시간·양품 정의가 확인된 설비에만 선택 표시한다. 정의가 없으면 가동시간·수량·불량률만 보여주고 임의 OEE를 만들지 않는다.

### S09 에너지와 계량기

대상: 에너지 담당자·ESG 분석가. 계량기, 측정 구간, 누적값/구간값, 배율, 단위, 계측 범위, 상위/하위 계량기 관계를 등록한다. 결측·중복·역전·롤오버·교체·범위 중첩을 표시한다. 원자료와 배분 결과는 다른 탭으로 분리한다. 공유 전력에 배분할 작업/제품/비생산 부문, 기준량, 정책 버전, 잔여량, 검토 상태를 보여준다.

### S10 데이터 수집과 오류함

대상: 데이터 관리자. CSV 템플릿과 열 매핑, 단위 변환, 미리보기, 오류 행 다운로드, 승인 후 반영을 제공한다. import batch 단위의 건수·합계·출처 해시·누가 가져왔는지·중복 판단을 기록한다. 부분 반영 여부를 미리 보여준다. v1은 파일 단위 검증 완료 후 반영을 기본으로 하고, 부분 반영을 지원한다면 성공/실패 행을 재시도해도 중복되지 않게 한다. API 지연과 마지막 성공 시각, 원천과의 차이를 같은 오류함에서 처리한다.

### S11 운영 검토와 기간 마감

대상: 생산 관리자·품질 승인자. 작업지시 완료, 로트 수량수지, 미처리 WIP, 품질 보류, 단위 변환, 에너지 데이터 상태를 한 체크리스트에서 확인한다. 차단 오류와 경고를 구분한다. 경고를 수용할 때 사유와 승인자를 남긴다. 생산 운영 마감과 PCF 입력 마감은 구분되며, 생산은 정상적으로 마감됐지만 탄소 근거는 아직 부족할 수 있다.

### S12 탄소 입력 준비와 영향 분석

대상: ESG 분석가. 제품·기간·생산스냅샷별 입력 준비 상태, 실측/추정 비율, 누락자재, 미배분 전력, 공급사 자료를 보여준다. PCF 결과에서 수량 → 작업 → 공정 → 원천 이벤트 → 증빙으로 내려갈 수 있다. 원천 정정 시 영향받은 study와 공개 버전을 목록화하고 재계산 요청을 만든다. MES 화면에서는 계수만 바꿔 낮은 탄소값을 만드는 기능을 제공하지 않는다.

### S13 승인과 감사 기록

대상: 승인자·감사 열람자. 누가 언제 어떤 데이터를 만들고 변경·승인·반려·내보냈는지 본다. 권한 변경·지원 접근·증빙 다운로드도 포함한다. 현재 유효값과 당시 승인된 값을 각각 재현한다. 감사 기록은 일반 사용자가 수정·삭제할 수 없다.

### S14 운영 지표와 알림

대상: 공장장·담당자. 납기 위험, 미처리 보류, 입력 지연, 품질 처분 대기, 에너지 미배분, 산정 준비도를 보여준다. 알림에는 조치 책임자·대상·기한·원인과 바로 가기를 넣는다. 같은 원인에서 발생한 수십 건은 묶고, 읽음과 해결을 구분한다. 실시간 화면의 추정치와 승인 보고서의 확정값을 시각적으로 구분한다.


## 5 세 사용자와 종단 시나리오


### 시나리오 A 생산관리자와 작업자의 정상 생산

가상의 부품 제조사에서 생산관리자는 알루미늄 브래킷 100개 지시를 만든다. 품목 rev3, BOM rev5, 라우팅 rev2를 선택해 배포한다. 작업자는 승인된 원료 로트를 스캔하고 실제 소비 115kg을 기록한다. 최종 제품의 실측 또는 승인된 근거 질량은 개당 0.8kg이다. 최초 검사에서 90개 적합, 10개 재작업이 발생한다. 재작업 후 10개가 회복돼 최종 양품은 100개다. 가공 칩·폐기물이 35kg이면 이 예시의 물질수지는 115=80+35kg이다. 추가 포장·보조재·손실은 이 단순 예시 밖이며 실제 범위에서는 별도로 기록한다.

재작업의 추가 시간과 전력은 원 작업에 연결한다. 시스템은 110개 생산이라고 표시하지 않는다. 생산관리자는 미결 품질건이 없고 수량이 맞는지 확인한 뒤 운영 마감한다. ESG담당자는 마감된 생산 100개와 실제 원료 115kg을 사용하며 계획 BOM 투입량을 슬쩍 대체하지 않는다.

완료 기준: 한 작업의 입력부터 최종 100개·폐기 35 kg·재작업 10개의 관계가 유지되고 원료 로트와 검사·재작업 증빙까지 추적된다.

### 시나리오 B 품질담당자의 부분 보류와 계보 추적

검사자는 완성 로트 L100의 100개 중 20개에서 추가 검사가 필요하다고 판단한다. 20개를 보류 자식 로트 L100-H로 분리하고 나머지 80개는 별도 가용 상태로 둔다. 보류분을 다른 로트와 합치거나 다음 공정에 확정 투입하려 하면 차단한다. 품질 승인자는 15개 재검 적합, 5개 폐기로 처분한다.

이후 원료 공급자가 한 원료 로트의 품질 이슈를 알렸다는 상황을 가정한다. 품질담당자는 해당 원료를 소비한 작업과 파생 로트, 다른 로트와 병합된 제품, 이미 사용된 수량을 조회한다. 시스템은 '조회된 계보 범위'를 제시하고 고객 통보·회수 실행을 자동으로 하지 않는다. v1의 출하 이력이 외부 ERP에 있다면 마지막 확인된 출하 참조와 조회 한계를 표시한다.

완료 기준: 80+15 가용과 5 폐기, 처분 전후 계보, 승인자, 영향받은 산정 입력이 함께 맞는다. 완제품 재검·폐기 시점에 따라 어느 생산기간의 분모·부담을 수정할지는 ESG 검토 항목으로 남긴다.

### 시나리오 C 에너지와 ESG 담당자의 공유 계량기 마감 및 정정

에너지 담당자는 한 구간 총전력 1000kWh에 대해 제품 A600, 제품 B300, 미배분 100을 확인한다. 미배분 이유를 찾고 승인된 공용부하 정책에 따라 A60, B30, 기타시설 10으로 분류하면 운영상 A660+B330+기타시설 10=1000kWh가 된다. 이 숫자는 계산 예시이며 수지가 맞는 것만으로 산정 경계가 닫히거나 배분이 타당해지는 것은 아니다. 기타시설 10이 제품 A/B를 지원하는 공용시설이면 추가 배분이 필요하고, 다른 제품 C의 전용공정으로 확인돼야 A/B에서 제외할 근거가 생긴다. 일반적인 '기타'로만 남아 있으면 최종 산정 승인을 막는다.

ESG담당자는 승인된 allocation revision1과 생산스냅샷을 선택해 산정한다. 다음날 원천 CSV에서 전력 배율 오류가 확인되면 에너지 담당자가 정정 요청한다. 승인된 새 원천과 배분 revision2가 만들어지고 기존 PCF는 '원천 데이터 변경, 재검토 필요'가 된다. 공개 revision1 파일은 그대로 보존한다. 재계산·검토·승인을 거친 새 PCF만 새 버전으로 공유한다.

완료 기준: 총량 검증, 원본+배분 이중계산 방지, 정정 전후 재현, 영향받는 모든 산정 결과의 누락 없는 표시가 가능하다.


## 6 화면 검토 완료 조건

- [ ] S01부터 S14까지 각 화면의 입력·역할·오류·빈 상태·다음 행동을 검토한다.
- [ ] 작업자·생산관리자·품질담당자와 정상·부분보류·재작업·정정 시나리오를 수행한다.
- [ ] 화면의 수량과 데이터 원장의 동일 의미를 확인한다. 생산량·통과량·출하량을 혼용하지 않는다.
- [ ] 작업자의 입력 시간이 측정됐고, 장애 시 실제 공장에 맞는 대체 절차가 확인됐다.
