## 1 통합 승인 정책과 표준 필드 이름

이 파일을 MES와 탄소 모듈이 공유하는 의미 계약의 기준으로 삼는다. 구현 API나 테이블을 이미 확정한 것은 아니다. 외부 시스템의 용어가 다르면 이름을 억지로 바꾸기보다 아래 의미에 매핑한다.

| 대표 필드 | 허용할 외부 명칭 예시 | 의미와 규칙 |
|---|---|---|
| event_id | event ID | 제품 내부의 불변 사건 식별자 |
| source_event_id | source_record_id | 원천 시스템의 사건 식별자 |
| source_revision | source record revision | 원천 사건의 개정. 같은 ID와 같은 개정의 다른 내용은 충돌 |
| operation_run_id | operation_execution_id | 계획 공정이 아니라 실제 실행 세션 |
| occurred_at_utc | occurred_at | 실제 발생 시각. 명시된 시간대에서 UTC로 해석 |
| recorded_at_utc | recorded_at | 원천이 기록한 시각. 수신 시각과 구분 |
| ingest_received_at | received_at | 이 제품이 수신한 시각 |
| site_timezone | source_timezone | 사업장 시간대와 원천 시간대가 다르면 둘 다 보존 |
| supersedes_event_id | supersedes reference | 정정된 이전 사건을 가리키며 원본 삭제를 뜻하지 않음 |

초기 정정 표현은 revision과 supersedes 연결을 권고한다. 취소 전표 방식이 필요한 연계는 변환 규칙과 상쇄 의미를 별도 합의하며 두 방식을 같은 사건에 중복 적용하지 않는다.

시간 구간은 시작 포함·종료 제외인 [start, end)로 통일한다. UTC 구간과 현지 업무일·교대조 귀속은 별도 정보다. 같은 구간 경계에 들어온 이벤트가 두 기간에 동시에 포함되지 않게 한다.

에너지 담당자는 측정과 배분 driver 근거 및 배분 초안을 관리한다. ESG 담당자는 방법론상 배분 정책과 경계를 승인하고 사용할 개정을 선택한다. 양쪽은 같은 allocation ledger ID와 revision을 참조하며, MES에서 한 번 나눈 값을 ESG에서 또 나누는 별도 배분 원장을 만들지 않는다. 제품 기능으로 배분 도구를 양쪽 화면에 제공하더라도 저장되는 정책·결과는 동일해야 한다.

승인 분리의 통합 제안은 다음과 같다. 내부 추정·검토 작업에서는 작은 조직의 겸직을 기록 가능한 예외로 허용할 수 있다. 고객에게 공식 발행하는 결과는 작성자와 최종 승인자를 분리하는 것을 출시 정책으로 제안한다. 최종 내부 승인과 외부 공유 권한도 분리한다. 실제 계약과 고객 역할 배정 전에 확정하며, 예외가 필요하면 그 결과를 고객 발행 가능 상태로 자동 승격하지 않는다.

서비스 관리자 MFA와 최소 권한·격리·감사는 P0다. 고객 SSO·SCIM은 기본 확장 후보이지만 특정 고객의 필수 보안조건이면 해당 고객 도입의 선행조건으로 올린다. 기능 우선순위가 고객 보안 요구를 무시하는 근거가 되어서는 안 된다.

## 2 데이터 모델과 ESG 인터페이스


### 핵심 객체

| 객체 | 필수 속성 | 핵심 관계 |
|---|---|---|
| Tenant / Site | 불변 내부 ID, 표시명, 현지 시간대, 업무일 규칙 | 모든 레코드의 소유 범위 |
| Item / Material | 품목 ID, 외부키, 유형, 기준단위, 유효기간 | BOM·로트·계수 매핑 |
| BOMRevision | 개정 ID, 구성재료, 계획량, 승인·유효일 | 작업지시의 고정 참조 |
| RoutingRevision | 공정 순서, 작업장, 표준시간, 검사 지점 | 실행 세션과 분리 |
| WorkOrder | 목표량, 납기, 품목/BOM/라우팅 버전, 원천 | 여러 공정·생산 로트 |
| OperationRun | 실제 시작/종료, 설비, 작업조, 상태 | 실제 투입·산출·비가동 |
| MaterialLot | 품목, 원료공급자 로트, 생성·만료, 수량 버킷 | 계보 입력과 출력 |
| MaterialMovement | 투입/반납/이관/산출, 수량·단위·근거 | 작업·공정·로트 연결 |
| LotTransformation | 분할/물리적 병합/가공, 입력·출력 수량 | 시간·변환 이벤트로 펼친 계보의 순환 방지 |
| QualityRecord | 검사기준 버전, 결과, 표본 수, 판정 | 보류·처분과 연결 |
| Hold / Disposition | 대상·수량, 사유, 해제/재작업/폐기 승인 | 가용수량 통제 |
| DowntimeInterval | 설비·구간·사유·계획/비계획 | 가동시간 검증 |
| Meter / Reading | 범위, 시간구간, 수치·단위·배율, 품질 | 원자료만 저장 |
| AllocationLedger | 원천구간, 배분대상, 배분량·기준·버전 | 원자료와 따로 합계 검증 |
| Evidence | 문서 ID, 해시, 소유·접근범위, 출처·유효일 | 이벤트와 다대다 연결 |
| Correction | 원 이벤트, 새 개정, 사유, 승인 | 영향받는 스냅샷·study |
| CloseSnapshot | 기간·범위·확정 이벤트 개정 집합, 승인 | ESG 입력의 고정 참조 |

식별자는 표시용 로트번호와 불변 내부 ID를 분리한다. 같은 'LOT-001'이 다른 공급자·사업장·연도에 존재할 수 있다. 외부키는 source_system + external_id + tenant/site 범위와 함께 해석한다. 이름 변경·설비 이동·품목명 변경은 과거 링크를 끊지 않는다.

실제 공정에는 재작업과 내부 회수의 순환이 있을 수 있다. 계보의 순환 방지는 이를 금지한다는 뜻이 아니다. 새 실행과 시간·변환 이벤트 또는 자식 상태를 만들어 이전 투입과 새 산출을 구분하고, 자기 자신이나 이미 소비한 조상 상태를 다시 사용해 수량이 생성되는 계보 오류를 차단한다. v1의 재작업은 지원하되 복잡한 재용융·폐쇄순환 공정은 별도 범위다.

### 공통 이벤트 필드

- event_id: 이벤트의 불변 식별자. source_system, source_event_id, source_revision은 원천 중복 방지와 대응에 사용한다.
- tenant_id, site_id, work_order_id, operation_run_id, lot_id, item_id, material_id, asset_id: 해당되는 연결만 명시하며 연결되지 않은 값은 임의로 채우지 않는다.
- event_type, schema_version, revision, supersedes_event_id, correction_reason, approval_state: 의미와 정정 관계를 고정한다.
- occurred_at_utc, recorded_at_utc, source_timestamp, site_timezone, business_date, shift_id: 실제 발생·수집·업무일을 구분한다. 기간 자료는 start/end 구간도 보관한다.
- quantity, unit, quantity_basis, measurement_method: 개수·질량·부피, 순중량/총중량, 습식/건식, 실측/추정/표준값을 구분한다.
- original_quantity, original_unit, conversion_rule_id, conversion_revision: 원본값을 보존하고 변환 결과는 별도 둔다.
- source_type, source_record_uri 또는 안전한 참조, import_batch_id, evidence_ids, data_quality_flags: 수기·CSV·API·계측의 출처와 증빙을 둔다.
- actor_id, reviewer_id, approval_time, scope, valid_from/to: 책임·유효범위·승인을 기록한다. 작업자 개인정보는 탄소 외부 공유에 기본 포함하지 않는다.

### MES가 ESG에 공급하는 이벤트

| 이벤트 | 전달 내용 | ESG 사용 원칙 |
|---|---|---|
| MaterialConsumed / Returned | 실제 재료량, 로트, 공정, 단위·근거 | 계획 BOM로 실제 소비량을 덮지 않음 |
| ProductionReported | 처음 통과 양품, 불량, 검사대기 | 최종 출하가능량과 구분 |
| ReworkStarted / Completed | 원수량·회복량, 추가 투입·시간 | 동일 실물의 신규 생산 중복 금지 |
| ScrapRecorded | 폐기량·질량·유형·처분 경로 | 자동 회피배출 크레딧 없음 |
| LotSplit / LotMerged | 부모·자식·수량·유형 | 배출부담 계승과 물질흐름 근거 |
| QualityDisposition | 해제·재작업·폐기, 유효시각 | 분모·제품 상태 검토 |
| MeterReadingValidated | 원 계량값과 범위·구간 | 원자료로만 보관 |
| EnergyAllocated | 원천구간·대상·배분량·방법·잔여 | 배분된 값만 대상제품 입력으로 선택 |
| OperationClosed / PeriodClosed | 확정집합·마감범위·워터마크 | 결과 재현 가능한 입력 스냅샷 |
| SourceCorrected | 새 개정·대체관계·영향 범위 | 새 study revision과 재승인 대기 |

전달은 최소 한 번 전송될 수 있다고 가정하고 멱등 수집한다. 같은 source_event_id·source_revision과 같은 내용은 중복 수락으로 처리하되 두 번 집계하지 않는다. 같은 source_event_id·source_revision인데 내용이 다르면 조용한 덮어쓰기 없이 충돌 처리한다. 순서가 뒤바뀌면 연결 대상이 올 때까지 대기·격리하고 마감에는 포함하지 않는다. 사용자에게는 단순한 성공·오류 건수와 해결 경로를 보여준다.

### 수량과 단위의 불변 규칙

1. ea와 kg는 같은 물리량이 아니므로 품목별 검증된 중량 또는 실제 계량 없이는 바꾸지 않는다.
2. m³와 Nm³, 습량과 건량, 총중량과 순중량은 자동 동등 취급하지 않는다.
3. 정밀도와 반올림 규칙은 표시와 원장 저장에서 구분한다. 허용 오차는 단위·공정·계측기 기준으로 승인하고 누적 오차를 숨기지 않는다.
4. 작업지시 목표량, 공정 통과량, 최종 양품량, 출하량은 서로 다른 지표다.
5. 재작업 회복량을 전체 생산량에 다시 더하지 않는다. 동일 로트의 품질 버킷 전환과 추가 공정부담만 기록한다.
6. 분할 전 부모수량은 분할 후 자식수량+부모 잔량과 같아야 한다. 이미 소비한 수량을 분할하지 않는다.
7. 물리적 병합 시 부모별 수량과 특성, 품질 상태를 유지한다. 부적합 부모를 섞어 적합 로트를 생성할 수 없다.
8. 질량수지는 폐기·반납·재공·손실을 포함한 해당 경계에서 검증한다. 개수 수지와 질량 수지를 무리하게 같은 식으로 강제하지 않는다.

### 에너지 이중계산 방지

원 계량기 구간과 그 배분은 서로 다른 종류의 레코드다. 제품 계산은 선택된 배분 결과를 사용하고 원자료 총량을 다시 더하지 않는다. 상위 계량기에 하위 계량기가 포함되면 상위 총량+하위 총량으로 합산하지 않는다. 전체를 상위에서 배분하거나 하위를 직접 귀속하고 상위 잔여를 계산하는 정책 중 하나를 선택한다.

각 원천 구간은 배분대상 합계+명시적 미배분량=검증된 원천량이어야 한다. 반올림 오차를 허용하더라도 정책의 오차 범위 안에서만 닫는다. 배분률 100%를 맞췄다는 이유만으로 타당한 배분이라 인정하지 않는다. 가동시간, 생산중량, 설비전력×시간 등 선택 기준의 근거와 대표성, 유휴부하, 공용시설부하 처리를 검토해야 한다.

청구서는 계량값과 대사하는 증빙일 수 있다. 실제로 다른 범위나 기간의 소비량을 추가하는 경우에만 별도 입력이며, 기존 미터와 중복 범위는 먼저 해결한다. 발전량, 외부 구매전력, 외부 송전, 저장장치 충방전도 측정 범위를 구분하며 v1에서 복잡한 전력 수지를 자동 지원한다고 주장하지 않는다.

## 3 상태와 승인 모델


### 서로 다른 세 상태축

1. 데이터 운영 상태: Received → Validated → Reconciled → Closed. MES 담당자가 관리한다.
2. 연구·계산 상태: Draft → Data ready → Calculated → In review → Approved → Superseded/Withdrawn. ESG 담당자가 관리한다.
3. 배포 상태: Not shared → Release authorized → Shared → Replaced/Revoked. 외부 공유 권한자가 관리한다.

MES가 마감됐다고 외부 PCF가 승인된 것이 아니고, 연구가 승인됐다고 모든 고객에게 공유할 수 있는 것도 아니다. 시스템 역할과 실제 위임을 구분한다.

### 상태 전이 규칙

- Draft에서 경계·분모·기간을 정의하지 않으면 Data ready로 못 간다.
- 계산 실패는 실패 Run으로 남고 수정 후 새 Run을 생성한다. 실패 결과를 부분 성공처럼 승인하지 않는다.
- In review의 입력은 동결한다. 변경 요청은 검토 반려 또는 새 revision으로 진행한다.
- Approved는 불변이다. 오탈자만 바뀌는 보고서도 report revision과 변경 이유를 남긴다. 계산내용 변경이면 새 Run과 새 승인이 필요하다.
- 외부 검증 상태는 Not assessed/Supplier claimed/Verification evidence attached/Scope checked 등으로 따로 관리한다. 내부 Approved를 외부 Verified 배지로 바꾸지 않는다.
- Withdrawal은 과거 발행을 없애는 삭제가 아니다. 철회 이유·시각·대체본·공유처를 기록한다. 다운로드된 파일을 회수할 수 있다고 약속하지 않는다.
- 고객에게 발송하는 행위는 승인된 대상·항목·목적 범위에 한정한다. 초기에 발송 자동화 없이 다운로드 패키지와 발행 원장부터 시작할 수 있다.

## 4 변경과 재산정


늦은 MES 이벤트, 계수 새 버전, 공급사 정정, BOM 오류 발견, 할당 정책 변경은 서로 다른 변경사유다. 영향 분석은 어느 제품·기간·Run·공유 패키지가 영향을 받는지 보여준다.

원본 정정은 supersedes 또는 reversal/new event로 표현한다. 기존 이벤트·승인된 스냅샷·Run을 수정하지 않는다. 불필요한 민감 원자료 보존과 법적 삭제 의무가 충돌할 수 있으므로 보존정책·계약·법무 검토를 별도로 설계하고, 불변 계산 근거의 보존을 무기한 개인정보 보관으로 해석하지 않는다.

재계산 결과는 배출량 변동을 활동량 변화, mix 변화, factor 변화, method 변화, data correction으로 설명한다. 계수 개선으로 수치가 떨어진 것을 제조 개선으로 보고하지 않는다. 비교하려면 고정 기준으로 다시 계산한 bridge 분석을 제공한다. 서로 경계가 다른 결과는 나란히 표시하더라도 변화율 또는 '더 친환경' 순위를 자동 산출하지 않는다.


## 5 MES와 탄소 담당자의 데이터 책임

### 핵심 데이터 묶음

| 계약 객체 | MES가 책임지는 사실 | ESG가 추가하는 의미 |
|---|---|---|
| Material consumption | 실제 투입·반납·이동·로트·단위 | upstream 계수, 공급사 PCF 경계, 방법상 포함 |
| Production output | 최종양품·재작업·폐기·WIP·분할합류 | 기준단위 분모와 기간 귀속 |
| Meter observation | raw 읽기·구간·계량기 계층·품질 | 배분 정책과 에너지 경계·계수 |
| Rework execution | 어떤 대상이 어떤 공정을 다시 수행했는지 | 추가부담 귀속, 분모 중복 금지 |
| Scrap movement | 양·처리처·내외부 이동·증빙 | 방법상 waste/coproduct/recycling 판단 |
| Closed snapshot | 확정 이벤트 집합·cutoff·watermark·revision | study 범위에 맞는 선택과 입력동결 |
| Correction | 이전 기록을 대체/취소하는 새 기록 | 영향 연구 탐색·재검토·재발행 |

MES 운영 사실에 ESG가 직접 수정을 쓰지 않는다. 잘못된 실적은 MES 정정 요청으로 돌린다. ESG 계수·배분·승인 정책은 MES raw event를 바꾸지 않는다. imported authoritative domain과 lightweight execution domain의 소유권을 사이트별로 정한다.

전달은 at-least-once를 견디는 idempotency, 순서 역전, 지연 도착, 부분실패, 단위 변환 버전, 삭제 대신 정정 semantics를 갖춰야 한다. 같은 source ID+revision을 재수신하면 합계가 늘지 않고, 같은 ID에 다른 payload가 오면 조용히 덮어쓰지 않고 충돌로 격리한다.

원시계량 수지와 할당수지, 물질수지는 다른 검사다. 물질수지 115=80+35가 맞아도 배출계수 경계가 틀릴 수 있고, 할당합 1000이 맞아도 기타 10의 제품 귀속이 부정확할 수 있다. 모든 검사에 '통과했으니 탄소 정확성 인증'이라는 의미를 부여하지 않는다.

## 6 멀티테넌트와 보안 및 권한


### 역할 제안

| 역할 | 주요 권한 | 금지 또는 별도 권한 |
|---|---|---|
| Tenant owner | 회사 설정, 계약·보안 담당 지정 | 자동으로 모든 기밀 증빙 열람·외부발행 권한을 주지 않음 |
| Data operator | 지정 site의 ingest·mapping·정정 요청 | ESG 결과 승인·다른 site 접근 |
| Carbon analyst | study·계수 후보·배분·시나리오 작성 | 자기 작성본 공식 승인, 무단 고객 발송 |
| Reviewer | 근거 검토·반려·조건 확인 | 원천 수정 |
| Approver | 최종 내부 승인 | 별도 위임 없는 외부 공유 |
| Commercial publisher | 승인본의 허용된 공개 항목 발행 | 계산·근거를 임의 변경 |
| Supplier user | 자기 요청·품목·자료 업로드 | 타공급사·전체 BOM·고객 판매량 |
| External verifier | 승인된 기간·study의 제한적 읽기 | tenant 전체 export·구성 변경 |
| Support operator | 제한된 진단 메타데이터 | 기본 상시 고객 원자료 접근 |

권한은 tenant→site→product/study→artifact→action으로 범위를 명시한다. API, 검색 색인, RAG, 파일 미리보기, export, 캐시, 비동기 job, 로그까지 같은 격리를 적용한다. URL의 study ID만 바꾸면 다른 회사 자료가 보이는 문제를 모든 경로에서 테스트한다.

SSO/MFA/권한검토는 B2B 요구에 따라 제공하며 서비스 계정은 읽기 범위와 만료·회전 정책을 갖는다. 운영 설비 제어권을 갖지 않는 읽기 연계가 초기 기본이다. 업로드 문서는 악성코드 검사·파일형식·용량 제한·격리를 거치고, 문서 안의 명령을 AI 실행권한으로 취급하지 않는다.

데이터 지역, 하위처리자, 암호화, 백업, 보존기간, 고객 export, 해지 후 반환·삭제, 사고 통지, 관리자 임시 접근을 계약 전에 합의한다. 실제 적용 전 규제·법무 검토가 필요한 항목이다. '보안 완벽' 또는 취득하지 않은 SOC/ISO 인증을 판매 문구로 사용하지 않는다.

지원자의 고객 데이터 접근은 시간제한·목적·승인·기록을 남긴다. 사용자 계정 정지는 즉시 권한을 차단하고 기존 token·공유링크·작업에 어떻게 반영되는지 테스트한다. 승인자 퇴사 때 과거 승인 기록은 보존하되 새 권한 위임은 별도 절차다.


## 7 데이터 소유와 보존 및 복구 원칙

### 보안과 데이터 관리

- tenant 격리 테스트를 API·DB 조회·검색·캐시·파일·비동기작업·내보내기까지 포함한다. 사업장 제한도 별도 검사한다.
- 전송·저장 암호화, 최소 권한, 관리자 MFA, 세션만료, 비밀정보 관리, 취약점 점검, 접근·변경 로그를 출시 요건으로 둔다. 인증 취득 여부와 이 기능의 유무를 혼동하지 않는다.
- 파일은 악성형식 검사와 크기 제한, 만료되는 접근 토큰, 다운로드 권한을 둔다. 외부 공유는 명시된 제품·기간·자료만 대상으로 한다.
- 고객자료로 모델 학습 또는 다른 고객 벤치마크를 하지 않는 것을 기본 정책 가설로 둔다. 향후 다른 사용은 별도의 권한과 계약이 필요하다.
- 데이터 소유자, 처리지역, 위탁업체, 보존기간, 계약종료시 반출·삭제 절차를 계약서와 운영정책에 명시한다. 법정 보존기간을 임의로 단정하지 않는다.
- CSV/표준형식으로 기준정보·이벤트·스냅샷·증빙목록을 반출할 수 있어야 한다. 고객을 붙잡기 위해 내보내기를 유료장벽으로 막지 않는 방향을 제안한다.
- 원장과 첨부는 백업만 만들지 말고 복원훈련을 한다. 삭제 요청과 보존의무 충돌은 고객 계약·법무 검토에 따른다.

### OT와 서비스 장애

본 서비스는 공장 제어가 아니라 업무 기록·분석 시스템이다. 인터넷 또는 SaaS 장애가 설비 안전정지 로직에 연결되지 않도록 한다. NIST OT 보안 지침은 OT의 성능·신뢰성·안전 요구를 고려해야 함을 강조한다. 이를 참고해 v1은 읽기 수집과 업무계층을 구분하고 현장 제어를 제외한다. [NIST SP 800-82 Rev 3](https://csrc.nist.gov/pubs/sp/800/82/r3/final)

서비스 장애 시 고객은 승인된 현장 수기 양식으로 작업 사실을 기록하고 복구 후 가져온다. 이 절차로 생산을 계속할 수 있는지는 공장별 품질·안전 요건으로 판단해야 한다. 본 제품은 대체 안전체계가 아니다. PLC에 직접 외부망을 열지 않고 추후 커넥터도 고객 IT/OT 검토, 읽기 권한, 변경관리, 네트워크 분리를 전제로 한다.

## 8 보존 정책과 계약 종료 시 확인할 항목

아래 기간은 출시 전에 고객·계약·법무 검토로 확정한다. 법정 의무를 임의 숫자로 단정하지 않고, 미결정 항목이 있는 상태로 장기 보존을 약속하지 않는다.

| 자료 | 소유와 목적 | 출시 전 확정할 보존 및 삭제 조건 |
|---|---|---|
| 생산 사건·기준정보·첨부 | 고객 업무 자료. 서비스 제공에 필요한 처리만 허용 | 계약 기간, 감사 필요 기간, 증빙 라이선스, 삭제 요청과 예외 |
| 스냅샷·계산·승인본 | 고객 결과와 재현 근거 | 원천 삭제 시 재현 한계 표시, 정정·철회 이력 보존 범위 |
| 감사·보안 로그 | 접근·변경·사고 조사 | 최소 필요 개인정보, 열람 역할, 보존 기간과 법적 보존 조치 |
| 백업 | 장애 복구 | 회전 기간, 삭제 반영 시차, 복구 시 삭제 상태 재적용 |
| 공급사와 유료 계수 | 권리자 사용권에 따른 제한 자료 | 재배포·감사 열람·계약 종료 후 보관 가능 범위 |
| 사용자 계정 | 접근 통제 | 퇴사·탈퇴 즉시 접근 차단, 과거 승인자 기록의 최소 보존 |

해지 절차는 반출 범위와 형식 합의 → 권한 있는 요청자 확인 → 기준정보·사건·결과·증빙 목록 반출 → 수신 확인 → 접근 종료 → 계약상 삭제 및 백업 회전 → 처리 기록의 순서로 검증한다. 반출은 사용권이 없는 제 3자 원자료까지 넘길 권한을 뜻하지 않는다.
