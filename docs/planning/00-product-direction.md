# 제품 방향과 단계별 범위

> 상태: 기획 검토본 · 기준일: 2026-11-03 · 버전: 1.0
> 이 문서의 기능·운영·가격·성과 기준은 제안이며, 구현 또는 인증 완료를 뜻하지 않는다.

이 파일에서 첫 제품의 약속과 제외 범위를 먼저 결정한다. 기술·화면 상세보다 먼저 읽는다.

이 문서는 제조 현장의 기록과 제품 탄소 산정을 연결하는 B2B 서비스를 개발하기 전에 합의할 제품 기획이다. 목표는 기능이 많은 시연물을 만드는 것이 아니라, 한 고객의 실제 업무를 끝까지 처리하고 숫자의 출처와 변경 이유를 설명할 수 있는 제품을 정하는 것이다. MES 기획과 ESG 및 LCA 기획을 별도로 검토한 뒤, 데이터와 승인 절차가 만나는 지점을 하나의 제품 흐름으로 묶었다.

**권고 결론은 선택 제조단계의 데이터 수집과 검증부터 시작해, 근거가 확보된 범위만 제품 탄소 결과로 내보내는 것이다.** 처음부터 모든 제조업·모든 ESG 공시·모든 환경영향을 지원하지 않는다. 경량 MES와 기존 MES 연계는 서로 다른 진입 경로이며, 도착지는 동일한 검증 가능한 제조 활동 원장이다. 코드는 기획과 승인 기준이 합의된 다음 매핑한다.

이 문서의 산업, 고객 규모, 서비스 수준, 가격, 일정, 성공 수치는 검증할 **제품 가설 또는 목표**다. 특정 고객 데이터의 확보, 운영 실적, 표준 적합성, 인증 또는 외부 검증 완료를 뜻하지 않는다. 기능 설명은 계약 조건이 아니라 제품 의사결정의 출발점이며, 출시 전에 고객·운영·보안·도메인 담당자의 확인이 필요하다.

## 1 읽는 순서와 독자별 용도

- 제품을 결정하는 사람은 먼저 초기 범위, 출시 게이트, 보류 결정을 읽고 첫 고객에게 약속할 내용을 정한다.
- 제조 담당자는 작업·로트·품질·설비·실투입 상태와 예외 시나리오를 확인한다. 실제 작업자가 수행할 수 없는 절차는 출시 전에 고친다.
- 탄소 담당자는 산정 경계, 데이터 우선순위, 배분, 계수 버전, 근거와 승인 조건을 확인한다.
- Java와 Spring에 익숙한 개발자는 화면을 바로 엔티티로 바꾸기보다, 업무 사건·변하지 않는 사실·정정·계산 실행의 차이를 먼저 읽는다. 프레임워크와 저장 기술은 이후 선택한다.
- 구매·보안·고객 성공 담당자는 테넌트 격리, 데이터 소유권, 지원, 복구, 도입 및 계약 가설을 검토한다.

## 2 첫 제품에서 해결할 한 가지 흐름

현장 담당자가 실제 생산·투입·에너지 기록을 남긴다. 생산 책임자는 누락과 충돌을 해결하고 기간을 마감한다. 탄소 담당자는 산정 경계와 계수·배분 정책을 선택해 계산을 재현한다. 검토자는 근거와 한계를 확인한다. 권한 있는 승인자가 고객에게 내보낼 결과를 승인한다. 이후 원천 데이터가 정정되면 어떤 계산과 공유본이 영향을 받았는지 알 수 있어야 한다.

이 흐름의 완료는 대시보드가 뜨는 것과 다르다. 사용자가 숫자를 클릭했을 때 원천 기록, 단위 변환, 배분, 계수, 산정 버전과 승인자를 추적할 수 있고, 오류를 정정해도 예전 공유 결과가 조용히 바뀌지 않아야 한다.

## 3 단계별 범위와 출시 게이트

### 단계 0 선택 제조단계의 내부 시연

한 공장의 한 제품군과 선택 공정부터 시작한다. 제조 단계 내부의 활동과 배출을 다루는 gate-to-gate 범위를 화면과 출력물에 명시한다. 원자재 생산, 물류, 사용, 폐기 등 포함하지 않은 단계는 명시적으로 제외한다. 이 결과를 제품 전체 탄소발자국 또는 전체 LCA 결과로 소개하지 않는다. 초기 제조단계 MVP라는 출발점을 유지한다.

완료 증거는 정상 생산 1건, 불량·재작업 1건, 기간 마감 후 정정 1건의 종단 재현이다. 가상 계수와 가상 데이터는 데모임을 표시한다. 이 단계에서는 정확한 데이터 구조와 사용자 이해를 검증하며, 외부 제출 가능성을 약속하지 않는다.

### 단계 1 고객 데이터로 진행하는 제한 파일럿

실제 고객과 공장·제품군·기간·데이터 원천·승인자를 합의한다. 선택 제조단계만 계약한 파일럿은 그 경계를 유지한다. 원자재 상류와 필요한 운송·포장 데이터를 확보하고 방법론 검토를 통과한 경우에만 cradle-to-gate PCF 파일럿으로 확장한다. 범위 확장은 자동 승격이 아니라 고객의 사용 목적과 증거에 따른 별도 결정이다.

완료 증거는 재현 가능한 계산, 원천과의 대사, 누락·추정 표시, 역할별 승인 및 정정 영향 추적이다. 실제 데이터로 계산됐다는 사실만으로 외부 검증 또는 인증이 이루어진 것은 아니다.

### 단계 2 유료 출시

동일 핵심 흐름을 복수의 분리된 고객 환경에서 안정적으로 운영할 수 있어야 한다. 오류 메시지·온보딩·고객 지원·해지 후 반출·백업 복구·보안 점검·권한 차단 시험을 통과한다. 판매 문구와 계약서가 지원 범위를 일치시켜야 한다. 외부 공유본은 사용 목적, 산정 경계, 적용 방법론, 데이터 기간과 검토 상태를 함께 전달한다.

### 단계 3 업종과 연계 확장

복수 공장, ERP·기존 MES 연계, 다단 공정, 외주, 복합 제품과 고객별 제출 형식을 확장한다. 새로운 업종의 생산 논리를 기존 화면에 억지로 넣지 않는다. 도입 공수와 커스텀 비용을 측정한 뒤 표준 기능으로 채택할지 별도 프로젝트로 할지 정한다.

### 단계 4 분석 고도화

원장과 근거가 안정된 뒤 온톨로지, 지식그래프, 이상 탐지, 예측을 단계적으로 도입한다. GNN은 필수 출시 기능이 아니다. 단순 규칙·통계 모델보다 실제 의사결정에 도움이 된다는 근거가 있을 때만 상용 범위에 넣는다. 인증, 전사 ESG 공시, 다중 환경영향 LCA 및 EPD는 각각 별도 제품·도메인·검토 범위로 다룬다.

## 4 성공을 측정하는 공통 원칙

각 지표에는 분모, 측정 기간, 제외 조건과 책임자가 있어야 한다. 전체 이용자 수보다 실제 종료된 업무를 본다. 데이터 수집률과 실제 근거 확보율을 구분하고, 값이 존재한다고 품질이 높다고 판단하지 않는다.

- 현장 성공: 계획한 작업의 실적 입력 완료율, 입력 소요 시간, 누락 해결 시간, 정정 건수와 원인.
- 탄소 성공: 승인 가능한 활동 데이터 비율, 출처가 확인된 계수 비율, 동일 스냅샷 계산 재현성, 검토 반려와 수정 시간.
- 고객 가치: 제출 자료 준비 시간의 전후 비교, 데이터 요청 왕복 횟수, 고객이 스스로 처리한 두 번째 마감 비율.
- 사업 성공: 유료 전환 의사, 도입 투입 시간, 공장당 지원 시간, 반복 사용과 갱신 의사. 매출 목표는 인터뷰와 파일럿 이후 확정한다.

## 5 제품 책임을 분리하는 기준

MES는 실제 생산에서 무엇이 일어났는지 관리한다. 탄소 모듈은 그 사실을 어떤 경계와 정책으로 계산했는지 관리한다. 공유 모듈은 어떤 결과를 누구에게 어떤 목적으로 승인했는지 관리한다. 운영 관리자는 서비스 장애와 접근권한을 처리하지만, 고객 원천값이나 산정 결과를 임의로 바꾸는 권한을 갖지 않는다.

MES 마감, 탄소 검토 승인, 외부 공유 승인은 각각 다른 사건이다. 하나가 완료됐다고 나머지를 자동 완료하지 않는다. 반대로 탄소 계산 실패 때문에 현장의 생산 기록 자체가 유실되거나 중단되어서는 안 된다.

## 6 기획에서 구현으로 넘어가기 전 필요한 산출물

1. 첫 고객의 사용 목적과 공개할 수 있는 결과 범위가 적힌 1페이지 범위 합의서.
2. 정상·예외·정정 흐름을 포함한 화면 검토 기록과 담당자 승인.
3. 필수 필드, 단위, 식별자, 시간, 원천 권한, 정정 방식이 합의된 데이터 사전.
4. 예상값과 근거가 있는 계산 예제 및 실패 시험 목록.
5. 테넌트·역할·내보내기·지원자 접근·보존 정책과 이를 검증할 시험.
6. 기능별 우선순위, 출시 차단 항목, 보류 항목과 결정 책임자.

이 여섯 가지를 먼저 고정하면 Java 클래스나 API 설계는 업무 의미를 옮기는 작업이 된다. 이를 건너뛰면 구현 이후에 같은 필드가 계획값·실제값·추정값을 동시에 뜻하게 되거나, 정정과 삭제가 뒤섞여 재계산과 감사가 어려워진다.
## 7 초기 고객과 진입 경로 가설

### 첫 고객 가설

- 업종: 금속 절삭·가공 후 단순 조립을 수행하는 이산형 부품 제조사. 식품, 의약품, 반도체 공정, 연속화학, 제철 일관공정은 초기 대상에서 제외한다.
- 규모: 1개 사업장, 2~3개 제품군, 10~30개 SKU, 5~20개 주요 설비 또는 작업장, 생산·품질·ESG 관련 핵심 사용자 5~20명. 숫자는 인터뷰로 좁혀야 한다.
- 환경: ERP 또는 엑셀로 수주·재고를 관리하지만 작업 실적과 에너지 증빙이 분산돼 있다. 기존 고객사가 제품별 탄소자료나 원료 추적 자료를 요구한다는 문제를 가진 업체를 우선 검증한다.
- 첫 공정: 투입 → 가공 → 검사 → 포장처럼 순차적이고 반복적인 라우팅. 병렬 경로, 공제품 다량 발생, 재용융 순환, 장기 연속공정은 별도 설계가 필요하다.
- 경제적 구매자: 공장장 또는 제조기업 대표. 실무 챔피언: 생산관리자와 품질/ESG 담당자. 보안·구매 승인자: 고객 IT 또는 외부 전산담당자.
- 부적합 고객: 설비 실시간 제어가 필수인 고객, 기존 MES를 전 공장 동시 교체하려는 고객, 즉시 법정 인증 보고서를 요구하는 고객, 로트·생산량·에너지 원천을 제공할 수 없는 고객.

### 범용 MES와 기존 MES 연계의 선택

| 선택 | 장점 | 부담 | 권고 |
|---|---|---|---|
| 범용 MES 전체 교체 | 실행 데이터를 직접 통제 | 업종별 예외, 장비, APS, WMS, 정산까지 범위 급증 | v1 제외 |
| 기존 MES 위에 탄소 기능만 추가 | 현장 중단을 줄이고 기존 실적 활용 | 고객별 연계비, 데이터 누락과 버전 문제 | 기존 MES 고객의 별도 도입 경로 |
| 경량 MES와 증빙 원장 | 소규모 현장이 생산과 탄소를 함께 시작 | 작업자 입력 습관과 최소 실행 UX 필요 | 첫 파일럿 주 경로 |

초기 권고안: v1의 주 고객은 MES가 약한 공장으로 정하고, 수기·CSV 기반 경량 실행을 먼저 완성한다. API를 포함한 수집 구조와 식별자는 처음부터 공통으로 설계한다. 기존 MES 고객에는 작업 실행 UI 전체를 다시 쓰게 하지 않고 읽기 연계와 누락 근거 보완을 제공한다. 두 경로의 생산 사실을 같은 도메인에서 동시에 확정하지 않는다.

## 8 제품 경계와 용어


| 구분 | 제공하는 결과 | 필요한 추가 데이터 | 명확한 제한 |
|---|---|---|---|
| 선택 제조 단계 부분 탄소산정 | 지정 공정의 배출량과 양품 단위당 제조단계 탄소량 | 실적, 투입·산출, 계량, 배분, 해당 배출계수 | 원재료 upstream, 다른 공정, 사용·폐기가 빠질 수 있다. 전체 제품 PCF로 표시하지 않는다 |
| Cradle-to-gate PCF | 정의한 공장 출구까지 제품 기준단위의 기후변화 영향 | 원재료·부품 공급망, 입고물류, 외주, 포장 및 제조 증빙 | use/end-of-life는 제외된 부분 생애주기다. 제외를 보고서 첫 페이지에 표시한다 |
| Cradle-to-grave PCF | 사용·폐기 시나리오까지 포함한 기후변화 영향 | 수명, 사용 패턴, 전력 시나리오, 수리, 폐기·재활용 시나리오 | 미래 시나리오가 관측 사실인 것처럼 보이지 않게 한다 |
| 다영향 LCA | 기후변화 외 여러 영향범주의 벡터 | elementary flow 기반 LCI, LCIA 방법·특성화계수, 지역·구획 매핑 | kgCO2e 하나로 산성화·물사용·독성 등을 추정하지 않는다 |
| 전사 탄소관리 | 회사의 조직 경계와 기간에 따른 인벤토리 | 회사 전체 활동 및 조직 경계 | 제품 PCF 합산과 같지 않다. 제품 간 upstream 중복·재고·기간 차이가 있다 |
| 광의 ESG | 환경 외 사회·지배구조까지 포함 | 사람·조직·정책·통제 증빙 | 이 제품의 초기 출시 범위에 포함하지 않는다 |

ISO 14067 공개 설명은 제품 탄소발자국과 partial CFP를 다루며 기후변화라는 단일 영향범주에 한정한다. ISO 14040·14044 공개 설명은 목표와 범위, 인벤토리, 영향평가, 해석, 보고와 검토를 포함한다. 따라서 탄소 기능을 먼저 제공하면서 이를 완성된 다영향 LCA 또는 ESG 전반으로 홍보하지 않는다. [ISO 14067](https://www.iso.org/standard/71206.html), [ISO 14040](https://www.iso.org/standard/37456.html), [ISO 14044](https://www.iso.org/standard/38498.html)
